# 首次启动课程资料自动导入

## 已确认的体验

评委下载完整 GitHub 仓库并启动统一 Python 服务后，网页立即可用，默认“数据结构”课程在后台导入随仓库提供的 17 份 PPTX 和图片补录。知识库显示进度；完成后可直接关键词检索、查看实际页码及引用，无需密钥或手动执行导入命令。

采用后台导入，不采用阻塞整个服务启动，也不只在 Windows 启动器里导入。AI 生成回答、向量检索和自动 OCR 仍依赖各自外部服务，不自动启用或产生付费请求。

## 数据与生命周期

- 接入主应用的知识库生命周期，复用现有 Platform、SQLite artifact、FileStore、CPU JobQueue 和资料版本控制；不增加数据库、推理服务或 Node 后端。
- 复用现有资料包完整性校验，以及上传、解析、图片补录预览/采纳逻辑；内部协调过程不依赖本机 HTTP 登录或固定端口。
- 仅在没有历史文档的新数据目录中首次导入至 `course-default`。已有资料、归档或删除过资料的用户不自动添回演示内容；当前本机已导入的 17 份课件保持原状。
- 在既有 artifact 中持久化导入状态、资料包指纹及逐文档进度。成功后重复启动不新增文档、修订或作业。中途正常停止后可在下次启动继续，沿用幂等键，不覆盖用户改过的内容。
- 协调任务不占用一个长期 CPU 作业槽；实际解析和补录由原队列执行。关闭时先停止协调任务，再由原平台关闭队列、客户端和数据库。
- 资料缺失、hash 不符、解析失败或版本冲突时明确显示失败原因及修复指引，不用“已完成”掩盖部分导入，不自动反复重试失败任务。
- 提供 `.env` 开关关闭自动导入；测试构造应用可显式选择是否启用，避免无关回归全部被演示数据污染。

## 页面与兼容性

既有知识库 catalog 响应增量返回本课程的自动导入状态，原字段和 HTTP/SSE 契约保持。页面加载时显示准备/导入进度，并持续刷新到完成或失败，避免首次查询时静默显示空库。原有上传、筛选、检索、原文与问答流程继续使用。

## 验收

1. 从干净仓库副本/空数据目录启动真实 `backend.xueya.server`，不执行手动导入，页面和健康接口在导入期间可用。
2. 最终默认课程有 17 份资料、1112 页、1495 个片段；至少三组关键词与引用校验、浏览器原文打开通过，模型调用增量为零。
3. 第二次启动不增加课程、资料、修订或作业；中途停止后继续导入不重复。
4. 已有私人文档/笔记、归档或删除历史、自动导入关闭、资料包损坏/缺失和失败状态均有针对性检查。
5. 完整后端 `python -m pytest -q`、原前端回归及适用浏览器检查通过，更新首页和评委导入说明。

## 实施顺序

先补自动导入协调器与状态回归，再接应用生命周期和页面进度；随后更新说明，完成空库真实启动、重复启动与浏览器验收，再按当前 GitHub 交付流程发布并同步本地。
