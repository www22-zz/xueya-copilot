# C 学习功能前端接入方案（待确认）

## 目标与完成标准

将已合并 C 的学习服务接入现有学习空间，使用户能够在页面完成资料选择、生成、查看、预览、确认保存、练习、订正和复习，不需要手动调用接口。沿用现有页面和视觉风格；仅使用外部模型 API。新增业务数据保存到主平台同一个 SQLite 中，并在刷新、切换课程和重启后正确恢复。

“完成”指可走通实际业务流程，并有真实浏览器回归覆盖，不以新增按钮、演示数据或单独接口测试代替。

## 方案选择

1. **推荐：融入现有页面。** 让每个学习动作出现在用户原本使用的位置，复用统一的资料选择、生成进度和预览确认组件。需要同时补齐前后端数据适配，但能形成完整学习流程。
2. 新增单独的 C 学习中心。接入集中，但用户会遇到两套练习、计划和记忆卡，需要来回切换。
3. 只在聊天中提供快捷指令。改动较少，但不适合完整测验、作答订正和复习队列，因此不作为本次交付方案。

## 推荐的页面布局与流程

| 页面 | 本次增加或接通的功能 | 主要操作 |
| --- | --- | --- |
| 学习概览 | 今日学习、推荐反馈、章节学习包、已保存学习包 | 选择课程资料，设置学习时间，查看推荐，跳过/延后/恢复推荐，生成并预览章节学习包 |
| 资料问答 | C 的证据验证回答、章节总结/对照入口 | 选择当前资料，提问/总结，查看逐条出处与待核验标记；多资料对照提供相应入口 |
| 课程资料 | 完整章节选择与生成入口 | 从真实文档/章节进入学习包；完整章节总结不能用搜索前几条结果冒充覆盖全文 |
| 知识卡片 | 学习包要点、笔记编辑、历史版本 | 查看已保存产物，编辑后预览并明确确认；从来源建立记忆卡 |
| 练习与错题 | 候选题审核、测验组卷、作答、评分、主观题复核、错因诊断与订正 | AI 题先以候选形式展示，用户核对后采纳；测验提交前不展示答案；错因推测可被用户更正 |
| 记忆卡片 | 持久化卡片、FSRS 到期队列、四级复习评分、延后、历史 | 翻面后评分，按实际到期时间进入队列；修改卡片后按后端规则重新计算调度，保留历史 |
| 复习计划 | 生成预览、确认采纳、修改、重排、从学习包提取计划 | 设置考试日期、每天时间和不可用日期；预览影响后确认；生成学习包不自动覆盖原计划 |
| 知识图谱 | 真实概念/关系与学习路径 | 将已有图谱按 C 契约保存和读取；保留出处，区分待核对和已确认关系，拒绝先修环路 |
| 多模态学习 | 接入 C 已实现的图片、转写、语音与媒体分析服务 | 使用真实适配器和配置；识别结果先让用户校正，再进入解题或学习流程；配置缺失时明确提示，不生成伪结果 |

跨页面统一提供后台学习任务列表：生成进度、取消、刷新恢复、查看结果、等待用户补充、等待保存确认和结果不明时的人工选择。不会因为刷新而自动再次发起收费请求。

## 必须一起补齐的服务接入

- 新增统一的浏览器学习服务适配器，复用现有主平台初始化与鉴权，不在页面代码中重复管理密钥、令牌或数据库。
- 在主平台补齐学习产物、学习任务、候选题、记忆卡和版本的查询接口。列表分页并按课程隔离，所有写入继续使用版本条件、操作回执和确认机制。
- 将候选题审核后的结果保存到服务端题库，才能继续组卷、评分和诊断；不能只把候选题保存在页面变量中。
- 统一浏览器练习、计划、记忆卡与 C 的持久化对象映射。已有记录保留，无法证明题目版本/原文版本的旧记录标明限制，不伪造成完整学习证据。
- 读取真实知识图谱及边，补齐 C 当前只有概念、缺少边的上下文适配；新增图谱审核与学习路径接口复用 C 领域服务。
- 所有新增后端和验证脚本使用 Python。主入口保持 `backend.xueya.server`，不启动第二套平台，不覆盖 B 的 RAG 实现。
- 图片、语音与媒体服务复用主平台的 API 并发、调用账本和取消机制。只测试受控上游；真实收费测试需另有用户预算授权。
- 需要的比较、诊断、复习历史等 C 领域能力，如果当前未暴露 HTTP 路由，补充主平台接口再接前端，不让前端绕过后端拼装结果。

## 状态与数据规则

- 保存成功以服务端回执为准。未采纳的内容明确显示“预览”，失败时保留草稿，并提供重新预览或重试路径。
- 服务端学习产物与浏览器工作区同步采用明确的读写归属，避免旧浏览器完整快照覆盖新学习记录。切换课程、删除资料和更换文档版本时，清理无效选择并阻止过期证据采纳。
- 课程为空、资料不适用、没有已审核题、没有有效学习记录时呈现空状态和下一步动作，不填入虚构题目、诊断、掌握度、页码或引用。
- 页面显示“原文摘录”“模型生成”“待核验”等真实状态。没有语义审核器时不将模型改写冒充已验证结论。
- 原有纯浏览器与直接打开 HTML 的基础功能保留；服务端功能在不可用时说明如何启动本地服务，不显示保存成功或执行成功。
- 切换课程和离开页面时取消无效前台请求；后台持久化任务通过独立入口继续查看和控制。请求失败保留用户输入，冲突时重新加载并让用户核对。
- 动态文本、Markdown、引用和文件名安全渲染；表单可键盘操作，弹窗有焦点管理，手机布局可使用。

## 实施顺序

1. 建立接口/页面对照与服务适配器，补齐查询、候选题持久化和数据映射。
2. 打通资料 → 章节学习包 → 预览 → 确认保存 → 刷新恢复，接入任务控制。
3. 打通候选题审核 → 测验 → 提交 → 评分/复核 → 诊断订正，并接今日学习反馈。
4. 打通记忆卡、FSRS 队列、计划采纳与重排、图谱/学习路径及既有数据兼容。
5. 接入 C 已实现的多模态能力，明确配置、校正与取消流程。
6. 做完整后端和浏览器回归，更新使用说明及交付记录，列清已接入范围和实际配置要求。

## 验收

- 原有 170 项 Python 和 41 项前端回归继续通过；按实际新业务新增有意义的接口和状态回归。
- 浏览器覆盖：资料选择、完整学习包生成/确认/重启、候选题审核/组卷/作答/订正、FSRS 评分与到期、计划重排、图谱出处、推荐反馈、媒体校正和后台任务恢复。
- 额外覆盖跨课程、过期引用、重复点击、版本冲突、取消后不写入、无模型配置、空题库、不可用服务、直接 HTML 预览，以及手机和键盘操作。
- 测试使用隔离数据库与受控 API，不写入用户真实学习数据，不进行未经授权的付费调用。

本方案不包含新增模型训练、本地模型推理、多人云数据库或重新设计整站。实现完成后提供可检查的提交与验证结果；本次请求未重新授权合并/推送，发布 main 前遵循用户后续指示。
