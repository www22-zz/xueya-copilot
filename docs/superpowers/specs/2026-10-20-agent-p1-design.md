# Agent P1：动态规划与只读执行

用户已批准原升级方案并明确要求继续P1。只实现一次请求内的规划、工具选择、结果反馈与调整；P2持久恢复、P3/P4真实作答闭环不混入本次交付。

## 实施清单

1. 保留P0，并带入最新已提交的粘贴/已发送图片功能；不改主入口、现有HTTP/SSE路径、数据库或写入确认。
2. 在backend/agent增加规划协议、只读工具适配器、结果检查器和执行循环。通过现有模型端口请求JSON决策，包含初始计划及call_tool/revise_plan/ask_user/finish之一。
3. 复用官方MCP客户端与服务端白名单，开放现有搜索、读原文、进度、计划预览及可用的错题/图谱/复习队列查询。规划器只能看到可信宿主提供的输入schema与工具说明，不能设置身份、课程或确认写入。
4. 每步执行后核对结果与来源版本，再反馈观察。允许改写检索、改变工具与修改未完成步骤；已完成步骤保留。最多8轮、2次重规划，连续2次无新信息停止；与P0预算共享，格式错误/模型远端结果未知不自动收费重试。
5. 最终资料结论仍经过P0论断校验；学习统计和计划展示来自真实工具结果，不能由模型自报。缺少必需证据时不能声称完成。需要真实作答或补充条件时返回awaiting_user，用户后续发消息开启新请求，不宣称恢复原运行。
6. 由learning_integration提供主平台适配；/api/agent及流式端点接入，/api/ai、原题库/章节服务保留。默认开启文本Agent动态能力，可通过服务端开关回到固定流程；无模型及旧适配器保留原规则，图片识别沿用原路径。
7. 使用受控模型验证单章学习、错题巩固、备考三种只读准备场景及不同结果分支；验证越权/伪造来源/循环/取消/预算/更新竞态。按用户要求，执行相关专项、一次全量回归、前端回归与针对性浏览器检查，通过即收尾，不扩大反复检查。

## 数据与边界

计划包含目标、可核验完成条件和最多8个步骤；每个工具动作绑定步骤ID。模型不能将未执行步骤标为完成，也不能删除或改写已完成步骤。工具结果经过schema、课程、来源和大小检查；只将有界观察送回模型。进度、只读计划与来源保存在原run/checkpoint/result记录内用于审计，不创建新的任务队列或自动恢复协议。

三种学习场景共享同一循环。P1的完成表示完成资料准备/分析/计划预览，不表示用户已经完成练习、真实掌握或已保存任何业务产物。所有模型调用经主Provider、P0限额和账本，不引入本地模型、Node桥接或新Agent框架。
