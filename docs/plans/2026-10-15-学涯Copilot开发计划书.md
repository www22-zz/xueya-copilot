### 1.2 建议把项目做成什么

将项目定位为**面向个人课程资料的多模态学习助手**，围绕下列流程组织所有功能：

```text
课程资料或课堂截图
    → 解析并建立可追溯知识库
    → 提问 讲解 总结 与原文核对
    → 提取概念并形成笔记和知识关系
    → 练习诊断与错因分析
    → 生成个性化学习任务
    → 间隔复习和计划调整
    → 用新的作答结果验证是否学会
```

软件既要回答“这是什么”，也要进一步解决“我为什么做错”“下一步学什么”“学完后如何检验”。首页视觉、模型调用和工具数量都应服务于这条学习流程。

### 1.3 三个重点亮点

1. **可信多模态资料库**：扫描讲义、课件截图、图表和文本进入统一资料库；答案能够定位到真实原文和版本；支持对比、追问和资料不足说明。
2. **可解释的个性化学习**：题目关联知识点，区分知识缺口、计算错误和审题错误；结合掌握度、先修关系和间隔复习推荐学习任务，并展示推荐原因。
3. **能完成任务的学习 Agent**：从“解释概念”发展到“整理一章 → 生成小测 → 分析结果 → 提出复习安排”；通过 MCP 调用受控本地工具，支持停止、恢复和操作预览。

这些是项目拟形成的系统亮点，不预先宣称为学术原创算法。基础图文、诊断和受控MCP流程属于P0；先修图、复合学习包和通用检查点原标P1，现已纳入对应大任务完整范围。报告应说明自己的系统设计、数据和实验贡献，并承认开源算法与模型来源。

### 2.2 必须正确理解的边界

- 首页的动态知识球体是视觉设计，尚不是基于课程概念与先修关系构建的真实知识图谱。
- 当前“引用 ID 存在”不等于“答案每句话都被资料支持”；出题模块把无效来源回落到第一条来源的行为需要改为拒绝或重新生成，避免错误归因。
- 当前 MCP 是真实工具通信，但工作流仍由应用规则控制；不应宣传为已经具备任意自主、多智能体长期规划。
- 目前没有向量数据库、OCR、可靠的服务器资料库、账号和协作。当前服务默认仅绑定本机回环地址。
- 现有模型测试主要使用受控实现或本地模拟上游，不能当作真实 MiMo 质量、网络稳定性或付费使用量验证。
- “本地运行”指应用和资料库可在本机；调用 MiMo API 时，选定文本和媒体仍会传至外部服务，应在界面中说明。

### 3.2 核心用户流程与增强演示

A、B、基础C、E及F的取消/资料任务恢复属于P0演示；图谱先修路径、复合学习包和跨工具Agent断点继续属于P1，只有通过验收并进入冻结版本后才演示。

**流程 A 资料到答案**：导入一份含扫描页的讲义 → 查看 OCR 与索引状态 → 用同义表达提问 → 返回带依据答案 → 点击引用定位原页 → 保存可编辑笔记。

**流程 B 图片到理解**：上传课件截图或图表 → MiMo 识别图文关系 → 结合课程资料讲解 → 区分图像观察与资料结论 → 对看不清内容请求补图，禁止补造。

**流程 C 错题到学习路径**：P0为章节小测 → 评分和错因 → 薄弱概念 → 对应原文与练习 → 再测 → 展示掌握证据变化。P1增加先修图和路径可视化，不作为基础诊断的前置。

**流程 D 一句话完成学习任务**：P0保留单项问答、章节总结、出题和计划预览；P1将“整理这一章，再出五道题，最后建议三天复习安排”组织为复合学习包 → 展示步骤 → 分步处理 → 用户作答 → 分析与预览 → 明确采纳。没有作答时只能给通用安排，不能推断个人弱点。

**流程 E 复习与调整**：今日待复习列表 → 自评或测验 → 基础规则更新复习状态 → 未完成任务延期 → 剩余时间内重排 → 保留完成记录与计划版本。FSRS属于P1算法增强。

**流程 F 失败恢复与可信降级**：取消／断网／API限流或解析资源不足 → 说明阶段和限制 → 不保存半段答案 → 已保存资料与练习仍可用。P0解析/索引/章节总结由持久化任务提供最小阶段恢复；跨工具Agent工作流检查点继续属于P1。

## 四 技术架构与选型

### 4.1 统一运行架构

```text
浏览器：既有HTML/CSS/JS页面与离线学习规则
                ↓ 既有HTTP JSON / SSE
Python / FastAPI
  ├─ B：解析、分段、检索，后续接OCR/Embedding/Rerank API
  ├─ C：Agent、学习规则、MiMo与多模态API适配
  ├─ D：官方Python MCP SDK、stdio/HTTP、工具治理与确认
  └─ E：SQLite WAL、原件hash仓库、持久作业、备份恢复
       ├─ CPU：有界、可取消的普通解析进程
       └─ API：有界异步外部调用与用量/未知状态记录
```

后端不通过Node执行旧JS，API/作业/MCP是职责边界，不要求拆微服务。前端源文件与file:预览保留，Python学习规则与浏览器规则通过兼容基线验证。业务状态、模型结果和索引产物分开保存。

默认数据库已选SQLite，user_version=3；原件在.xueya-data/files。向量能力仍由B实际接入，不能把vector实体存储说成已实现向量检索。PostgreSQL/pgvector是未来规模扩大时的替换适配与一次性迁移，不同时维护两套默认产品。

### 4.2 推荐栈与采用条件

| 领域 | 主方案 | 选型理由和边界 |
| --- | --- | --- |
| 前端 | 当前HTML/CSS/JavaScript与既有视觉/交互保持；未来框架变更另行确认 | 先保住原页面与存储迁移；不将“全量换框架”列为所有功能的前置。若迁移，先单页等价回归。[React](https://react.dev/learn)、[Vite](https://vite.dev/guide/) |
| Python 后端 | 采用 Python 3.11+ 模块化单体与 FastAPI；公共边界用 Pydantic／JSON Schema，HTTP保持原字段 | 保留现有HTTP契约、前端和数据；后端统一Python，取消Node后端要求 |
| 关系与向量存储 | 当前SQLite WAL与版本化SQL；向量索引由B单独接入 | 资料、版本、学习事件与向量放在同一可管理底座；先精确向量查询验证正确性，再根据规模加 HNSW。[pgvector](https://github.com/pgvector/pgvector) |
| 扩展存储 | 规模需要时再迁PostgreSQL/pgvector，保留ID/CAS/事务契约 | 在主开发期只实现一个默认数据库；另一种保留接口和设计，不同时维护两套完整实现 |
| 原文件 | 本地受控 `data/` 目录与 StorageAdapter | 使用 hash、稳定版本 ID、相对路径与备份清单；后续可替换 S3 兼容对象存储 |
| 后台任务 | 数据库任务表 + 独立 Worker；必要时采用成熟 PostgreSQL 队列 | 任务事实不能只留在内存；设计幂等、重试和取消。吞吐需要时再评估Python任务队列与Redis，不增加JS后端 |
| 词法检索 | 中文分词与课程术语词典，配合数据库全文索引或经过测试的 BM25 实现 | PostgreSQL 的默认全文检索不能直接当作中文 BM25。比较实际召回后选定一种词法实现 |
| 向量与重排 | 外部Embedding与Rerank API，通过Provider接口接入 | 核查模型版本、中文质量、维度、数据授权、API权限和费用；不加载本地模型 |
| OCR／版式 | 对候选OCR/版式API做课程样本实测，选一个默认适配器 | 输出统一页、块、坐标和置信度；文本页直接提取，扫描页再 OCR，不每页都交大模型 |
| 主模型 | MiMo-V2.6-Flash 优先试验；复杂任务按实测升级 MiMo-V2.6-Pro | 官方已公布 V2.6 的原生多模态能力；账号权限、媒体 schema、限流和质量须实测。保留可配置模型与 Provider 接口。[MiMo 官方说明](https://mimo.mi.com/docs/en-US/news/latest/v2-6) |
| 学习算法 | 基础统计 + 可解释规则起步；FSRS 作为记忆调度候选；先修图辅助路径 | 算法输出与版本保存；数据不足时用默认参数和保守置信度，不宣称已准确预测学习成绩。[FSRS算法](https://github.com/open-spaced-repetition/fsrs4anki) |
| 图谱展示 | Cytoscape.js 或等价图组件；关系数据先存关系表 | 首页球体继续作为视觉入口；真实知识图谱需要可追溯节点和关系。Neo4j 为复杂图查询出现后再评估 |
| 观测与评测 | 结构化日志、request/run ID、离线评测脚本；按需要接 OpenTelemetry | 先能定位一次失败，再增加仪表盘；不以技术报告中的架构图代替真实观测 |
| 本地交付 | Windows 原生 Python 虚拟环境与启动脚本；数据库可用 Compose 或本机安装 | Python虚拟环境原生运行；SQLite无需Docker，外部API能力逐项验证 |

### 4.3 MiMo 多模态专项接入

当前配置中已有 `mimo-v2.6-flash`，但请求结构主要是文本消息。**只改模型名称并不等于完成多模态接入。**

1. 核对官方当前文档、控制台可用模型、API 地址、认证方式、请求字段与错误码。
2. 将消息内容从纯字符串扩展为经验证的文本、图片等内容块；按官方接口分别处理音频、视频和语音合成能力。
3. 为图片压缩、缩放、格式、体积和张数设上限；本地文件以受控方式转为 API 可读取的内容，不能把 `C:\...` 文件路径直接交给远程模型。
4. 对图像理解、音频理解、视频理解、工具调用、结构化输出和流式分别建立能力开关；一个功能可用不能推出其他功能可用。
5. 先完成小额真实 smoke test，再做固定样本质量评测；记录 model ID、日期、参数、耗时和用量，不记录密钥。
6. 模型更新后，先跑兼容评测，再切换默认配置。不得在提交前临时使用未经验证的新模型版本。

### 4.4 API与CPU资源控制

- 生成、OCR、Embedding、Rerank、ASR/TTS等所有AI能力只调用外部API，不引入本地模型、GPU/CUDA、模型加载或本地推理回退。
- Python负责普通解析、检索/学习业务、数据库和网络调用；CPU解析子进程与API各自有界，取消后等待底层资源退出。
- API逐项核查模型ID、请求schema、权限、体积/批量、限流、质量、用量与费用。未接入的功能明确未接通，不凭配置存在显示成功。
- 已发出但结果未知的付费请求进入unknown，不能自动重放；受控Mock、真实API和离线规则结果分别报告。

### 4.5 MCP 与业务工作流的边界

MCP 负责工具发现、调用和协议适配；Agent 负责业务任务规划、状态与用户意图。不要把业务运行记录塞进协议连接状态，也不要让模型直接决定任意文件路径和数据范围。

继续保留现有 stdio 接入，新增工具经过白名单和 schema 校验。需要远程工具时，再对 Streamable HTTP、授权、允许域和超时做独立适配。MCP 规范已有版本演进，后续应建立“锁定 SDK → 对应协议 → 传输 → 测试”的兼容矩阵，而非按旧示例假设所有新版都有相同初始化、会话和 GET SSE 语义。[MCP 版本规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning)、[HTTP 传输](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)

可增加的本地工具包括：读取章节结构、读取指定页、查询知识点、创建笔记草稿、生成待审核题目、查看待复习项、计算计划预览、导出学习包。写入笔记和采用计划必须走明确的操作预览与确认；检索读取不需要反复确认。

## 五 数据与接口约定

### 5.1 先统一的实体

| 数据域 | 主要实体 | 必须保存的关系或版本 |
| --- | --- | --- |
| 个人空间 | LocalProfile、Course、Chapter | 本地拥有者与 courseId；先保留默认课程，不要求先做完整账号系统 |
| 资料与索引 | Document、DocumentVersion、Page、Block、Chunk、Embedding、IngestionJob | 文件 hash、真实页／坐标、解析器版本、分块版本、模型版本与维度 |
| 会话与证据 | Conversation、Message、Citation、RetrievalTrace | 引用绑定资料版本、块、实际摘录与偏移；来源失效状态明确 |
| 学习知识 | Concept、ConceptEdge、Note、NoteVersion | 关系类型、来源、是否人工确认；笔记保留引用 |
| 练习 | Question、QuestionVersion、Quiz、Attempt、RubricResult | 作答绑定当时题目版本；正确答案与评分依据可追溯 |
| 记忆与计划 | MemoryCard、ReviewEvent、MasteryEstimate、StudyPlan、PlanVersion、PlanTask、Completion | 原始事件与派生状态分开；预览、采用、完成记录分开 |
| Agent 与工具 | AgentRun、RunStep、Checkpoint、ToolCall、UsageRecord | 任务状态、幂等键、取消、恢复点、工具结果、费用与错误 |
| 运维与导出 | Job、ExportManifest、BackupManifest、AuditEvent | 版本、校验和、重试与恢复记录 |

数据库字段使用稳定 ID；事件时间保存 UTC，界面与计划按用户时区展示，当前默认上海时区。重要关系使用外键与唯一约束，不把全部状态长期放入一个大 JSON 字段。

### 5.2 三个必须先评审的公共契约

**来源证据**：兼容现有 `id/title/location/quote`，逐步增加 `courseId/documentId/versionId/page/bbox/chunkId/quoteStart/quoteEnd/contentHash`。没有真实页码就标“文本段落”，不由模型补页码；模型不能凭一个字符串自己创造引用。

**学习事件**：保存 `eventId/courseId/questionVersionId/conceptIds/answer/correct/score/duration/createdAt/algorithmVersion`，可选 `responseExplanation`记录用户解题说明。`selfReportedConfidence`是学生自报信心，评分器不确定性和`masteryEvidenceLevel`另设字段；未经校准的规则分数不包装成统计概率。事件是事实，掌握度和复习日程是可重算结果。

**执行过程**：保存 `runId/taskType/status/stepId/eventId/schemaVersion/result/error/retryable/checkpointId`。SSE 只负责传输阶段与结果，断线重连先找原任务，不自动重发一笔付费请求。

文档Job的基本状态为`queued/running/succeeded/failed/cancelled`；Agent另外支持`awaiting_user/awaiting_confirmation`，等待期间释放计算资源。外部调用超时且结果无法确认时标记`outcome_unknown`并提供人工重试选择，不能仅凭本地幂等键承诺供应商不会重复扣费。

### 5.3 建议 API 族

| 接口族 | 主要作用 | 必须处理的边界 |
| --- | --- | --- |
| `/api/v1/profile`、`/courses` | 个人配置与课程范围 | 默认课程迁移、归档、范围过滤 |
| `/documents`、`/versions`、`/jobs` | 上传、索引、版本、原文查看 | 文件验证、进度、取消、重试、删除 |
| `/search`、`/sources` | 检索与证据读取 | 有效版本、课程范围、真实引用 |
| `/conversations`、`/runs`、`/runs/:id/events` | 会话与 Agent 任务 | 幂等、恢复、取消、最终结果 |
| `/notes`、`/concepts`、`/graph` | 笔记与知识关系 | 人工编辑、冲突、来源 |
| `/questions`、`/quizzes`、`/attempts` | 题库与诊断 | 题目版本、答案不泄露、评分与复核 |
| `/reviews`、`/mastery`、`/plans` | 复习与学习路径 | 调度版本、计划预览／采纳、时间预算 |

旧接口在迁移期继续存在，通过兼容适配调用新服务。新增契约从 schema 产生类型、Mock 和契约测试；只写 TypeScript 类型不能代替输入校验。

## 九 质量评测与验收

### 9.1 验证分为四层

| 层次 | 检查内容 | 验收证据 |
| --- | --- | --- |
| 确定性正确性 | 日期、统计、题目版本、幂等、迁移、引用位置、权限范围 | 单元、契约、数据库和真实 MCP 集成检查 |
| 完整用户流程 | 上传到问答、引用到笔记、练习到计划、停止和恢复 | 浏览器端到端记录，桌面与手机检查 |
| 模型与检索质量 | 召回、排序、事实支持、拒答、题目有效性、多模态理解 | 冻结问题集、人工评分表、真实模型输出与消融 |
| 可交付性 | 全新安装、一键启动、离线降级、备份恢复、报告一致性 | 安装录像、恢复记录、版本清单与提交包 |

普通 PR 使用受控模型，保证回归稳定且不重复消耗费用。真实 MiMo 评测使用单独命令、固定样本和用量上限；结果与受控模型测试分开呈现。

### 9.2 建议建立的 200 例评测集

| 类别 | 建议数量 | 主要检验 |
| --- | --- | --- |
| 单概念与精确术语 | 60 | 定义、条件、缩写、中英混合、公式和代码术语 |
| 跨段落或跨资料比较 | 40 | 多证据融合、冲突资料、概念对照 |
| 扫描页与图表题 | 30 | OCR、布局、图像理解和真实页定位 |
| 资料不可回答的问题 | 30 | 拒答、补充资料提示、无证据不编造 |
| 连续追问和上下文切换 | 20 | 代词、旧回答追问、明确换题、已删除资料 |
| 对抗与异常输入 | 20 | 资料内恶意指令、伪造引用、损坏媒体、超限和取消 |
| 合计 | 200 | 每例保留问题、资料版本、预期证据和判分口径 |

这些数量是正式评测目标，可以先建立 30 例开发集打通流程，再逐步扩充。不可答样本要经过人工确认；同一资料的重复改写不能充当大量独立样本。测试集冻结后不得依据失败答案反复改写测试期望来“提高分数”。

### 9.3 建议验收指标

下列数值是项目初始目标，10 月 20～24 日用固定环境测出基线后冻结；达不到时报告实际结果和原因，不能改写为“已经达到”。

| 领域 | 建议目标与统计方式 | 说明 |
| --- | --- | --- |
| 解析完整性 | P0核心样本的已识别标题/正文/表格/页顺序核验；未识别复杂结构留原图；状态可见 | 复杂公式表格单列W-021增强评测，不以抽到几个字判断整份成功 |
| 检索 | 可答文本子集Recall@5目标≥85%；按黄金原文证据区间计算覆盖比例后对问题取平均；另报至少命中一证据的问题比例 | 黄金证据独立于分块ID；多证据问题分别标注；图像表格子集单列；报告MRR/nDCG及基线差值 |
| 引用有效性 | 已返回引用的 ID/版本/摘录存在性应为100%；内容支持度抽样目标 ≥90% | 存在性可自动测，支持度需人工/辅助评审，二者不能混用 |
| 不可答处理 | 不可答样本正确说明不足目标 ≥90%，同时报告可答样本误拒答率 | 不要求单一分数同时代表幻觉、完整性与拒答 |
| 题目质量 | 抽样候选题 ≥90%满足有依据、答案正确、客观题唯一、解析可解释 | 标注审核前/审核后的结果和被剔除数量 |
| 学习统计 | 事件回放、最新错题、完成记录、日期和时间预算确定性测试全部通过 | 不允许以“模型差不多算对了”代替规则计算 |
| 原数据迁移 | 测试样本的资料/卡片/题库/作答数量、稳定ID与引用核对一致 | 无法迁移的字段清单可见；不静默丢失 |
| 取消与恢复 | P0长任务验证取消/断开与数据一致；文档任务验证阶段恢复；启用P1跨工具Agent检查点后另测 | 在线生成取消后不保证能续接同一模型输出；已完成产物不得丢失或重复写入 |
| 常规 API | 非模型、非大文件的常规操作 p95初始目标 <500ms | 硬件、样本量和并发固定；不要使用 mock数据代替真实数据库测量 |
| 检索延迟 | 热索引检索 p95初始目标 <1秒；启用重排后单独报告 | 允许依据本机结果调整，但必须保留调整理由 |
| 模型时延 | 单独报告首字、完整回答、超时率和失败回退 | 按模型/模态/网络/冷暖状态分组，不提前承诺统一秒数 |
| 内存与API资源 | 持续导入/问答具有有界并发和可恢复失败 | CPU解析进程、HTTP缓冲和API并发分别实测，不设置GPU运行要求 |
| 体验 | 第3.2节P0路径能在桌面和375像素宽度完成，P1按最终入选范围验收；键盘可完成主操作 | 记录任务成功率、耗时和实际障碍，不只询问“界面好不好看” |

若样本量小，应报告分子/分母和样本构成。例如“27/30个不可答样本正确拒答”，比单写“准确率90%”更可核查。学习效果结论还需要延迟测验和相同条件对照；短期软件测试不等于证明长期成绩提升。

### 9.4 技术报告建议完成的对照实验

1. **检索消融**：现有关键词、纯向量、混合检索；启用重排再增加对应组。固定资料、问题、模型、最终证据token预算，并报告候选数与延迟。
2. **分块对照**：固定字符与结构分块；使用独立于分块ID的原文件黄金证据；比较覆盖、上下文长度与答案支持度，控制最终证据token预算。
3. **多模态对照**：仅OCR文字与OCR加原图/视觉模型；在图表、扫描页和题目截图上分别评分。
4. **回答约束对照**：无资料直接问模型、基础RAG、带证据充分性与引用检查；比较支持度、拒答和完整性。
5. **学习策略对照**：固定练习/固定间隔与诊断推荐/候选FSRS；先用可回放事件验证工作量和调度，再用少量真实学习任务观察效果。
6. **资源对照**：CPU普通解析、API并发/批量策略、缓存前后；报告质量、耗时、峰值资源与成本的取舍。
7. **恢复实验**：同一任务在不同阶段中断，比较恢复成功、重复调用数和产物一致性。

其中1、2、3、4、6为本次报告优先实验；5只在样本和观察期足够时作效果分析，否则只报告设计和功能验证；7按进入提交版本的检查点能力执行。未实现的增强项不制作虚假的消融结果。

## 十 AI 辅助开发流程

### 10.1 一个大任务的持续执行

负责人领取/分配A～F整包 → AI阅读任务单与代码 → 自行整理内部依赖 → 在大任务分支分阶段实现与验证 → 更新专属进度文件 → 继续下一内部步骤 → 与真实模块接通 → 独立验收 → 负责人审查合并。

不是“每做一个小任务重新派发”。AI每阶段主动继续，遇到上下文或会话限制时保存检查点；下一轮读任务单、当前分支与`docs/delivery/large-*.md`续做。跨模块依赖未就绪时推进独立部分，不将Mock冒充真实联调。

### 10.2 给队友AI的入口

直接让AI执行对应`docs/tasks/大任务/`文件的完整指令，包含内部步骤、文件归属、接口交接、验收与持续执行要求。可复制的统一开场和续接指令见[派工入口](../tasks/README.md)。负责人只维护六行状态表；AI维护内部W项与证据。

普通技术选择和实现自主推进，不因任务大只交计划或第一步；必要凭据、资料或产品决定缺失时具体提问，同时继续不依赖它的工作。

### 10.3 AI 并行开发的安排

- 统一契约后，解析器、阅读器、模型适配、题库组件和评测脚本可以并行；不让多个上下文同时重写 `app.js` 和公共 schema。
- 不同任务使用独立分支/worktree，注明基线commit。共享库的变更先合并，再更新消费者。
- 一个开发上下文负责所属大任务的完整目标；内部自行分阶段并保存进度，其他模块的改动通过接口交接，避免越界重写。
- 向 AI 提供脱敏样例、接口和错误信息；真实密钥、私人资料与录音不用作无控制的上下文附件。
- 自动生成的解析、权限、模型输出处理和迁移代码必须重点审查。对高影响的文件删除、数据库收缩和工具写入，先有预览、备份与验证。
- AI 完成后要说明实际改了什么、怎么验证、未验证什么；不接受只说“已经实现”、只有截图或只通过自写Mock的验收。

### 10.4 每次合并的完成定义

- 功能走通：界面、接口、持久化和必要后台任务全部接线。
- 兼容清楚：旧数据、来源ID、取消和本地回退无无意回退。
- 异常可用：失败、超时、取消、重试和资源不足有明确行为。
- 检查适当：类型/静态检查和受影响的测试通过；涉及模型时补真实样本而非只加测试数量。
- 证据齐全：PR记录接口影响、验证结果和限制；技术报告素材同步保存。
- 可撤回：功能开关、兼容迁移或稳定版本可回退；不把代码回滚当成已经恢复被删除的数据。

## 十一 分支与合并协作

### 11.1 分支按大任务创建

继续以 `main` 为可运行主线。每个大任务使用自己的完整项目分支，内部小步骤分阶段提交，不要求为80项分别开分支：

```text
main
 ├─ feat/large-A-frontend
 ├─ feat/large-B-rag
 ├─ feat/large-C-agent-learning
 ├─ feat/large-D-mcp
 ├─ feat/large-E-platform
 └─ feat/large-F-quality-report
```

分支包含完整项目；不是只放负责模块的“分区”。用 Git 提交实际改动，不通过覆盖上传整个旧文件夹来表示某项功能。改到其他模块不自动等于犯错，应解释原因并做相关接口审查。可按已验收里程碑提前提交PR；阶段合并后同步main并继续同一大任务，不因一个小步骤合并就删除整个大任务分支或等待重新派发。

### 11.2 标准操作

以下操作在工作区已提交或妥善保存当前改动的情况下执行：

```bash
git switch main
git pull --ff-only origin main
git switch -c feat/large-B-rag

# 开发并检查，只添加本次实际修改的文件
git status
git add 具体文件路径
git commit -m "feat: add OCR page layout extraction"
git push -u origin feat/large-B-rag
```

创建 PR 时 base 为 `main`，compare 为任务分支；联调后合并。任务期间更新主线：

```bash
git fetch origin
git merge origin/main
# 有冲突时确认双方业务含义，修改后重新验证
```

不使用“全部保留我的”解决业务冲突。共享分支不要随意强推；以后也不要把所有分支重置为 main来同步，这会破坏队友未合并的工作。

### 11.3 高冲突文件的处理

| 文件类型 | 处理约定 |
| --- | --- |
| 公共schema | W-005先提小PR；说明兼容范围和消费者；对应Mock同时更新 |
| `backend/xueya/app.py` 与前端主控制器 | 模块先导出接口，集成工作项接线；避免整文件重写 |
| 数据库迁移 | 每项新增独立迁移，合并后不修改历史迁移内容 |
| `package.json` 与lockfile | 依赖变动单列并说明用途；冲突后用包管理器正确重新生成，不手工乱拼lock |
| CSS与通用组件 | 统一设计token和组件接口，业务页不各自复制一套弹窗/按钮 |
| 技术报告与实验表 | 章节与原始数据分目录；图表由脚本产生，最终由W-072统一汇总 |

推荐PR说明至少写“问题与结果、工作项ID、主要改动、接口/迁移影响、验证、限制”。仓库权限与套餐允许时启用 main保护、必需检查和禁止强推；这属于工程配置任务，不预先假设已经配置。

## 十三 资源预算和风险处理

### 13.1 本地资源与费用管理

1. **API/CPU资源**：外部调用与普通解析各自限制并发，取消后等待底层释放；记录用量和未知结果，不要求GPU或本地模型。
2. **内存与磁盘**：约32GB内存仍需给Windows、浏览器、数据库和模型缓存留空间；原文件、页图、音视频及模型权重各设清理规则与空间告警。
3. **付费API**：按任务记录模型、输入/输出、请求数、重试和真实账单；每日软上限与单任务预算可配置。正式使用前在控制台核对当日价格，不在计划书里固定未经确认的人民币预算。
4. **缓存**：区分开发Mock、已录制回放、真实缓存命中和实时生成；缓存键包含资料和模型版本；展示时准确标识来源。
5. **网络**：核心资料、笔记、题库、学习记录和规则计划本地可用；模型无法连接时说明降级。音视频处理不能依赖随意公开本机资料。
6. **本地安全**：默认只监听回环地址；文件接口验证类型、路径和大小；解析器设置时间/内存/解压上限；远程暴露前先做认证和权限。

### 13.2 风险与处理

| 风险 | 早期信号 | 处理方式 |
| --- | --- | --- |
| MiMo模型/API发生变化 | 模型不可用、字段拒绝、输出变化 | 能力表、锁定配置、真实小额兼容检查；经评测切换可用模型 |
| 外部API能力或权限不符 | 模型/字段不可用或限流 | 先核对官方文档并跑真实小样本；未接通明确标记，不伪造成功 |
| OCR/公式识别不准 | 错行、错单位、遗漏符号 | 保留原图和置信度；人工修正；优先支持明确样本类型并报告边界 |
| RAG答案引用看似正确但内容不支持 | ID有效、人工核对却不相关 | 论断级证据、无资料拒答、失败样本回归；报告分别统计有效性与支持度 |
| 题目或诊断错误 | 多个正确选项、错误归因 | 候选审核、明确评分规则、用户纠正、题目版本；不把模型评分当权威成绩 |
| 数据迁移或误删除 | 数量/ID不一致、文件缺失 | 迁移前备份、预览、事务和恢复演练；删除范围明确，不用整目录覆盖同步 |
| 模型并发/OOM/超支 | 任务积压、峰值超限、反复重试 | 统一队列、并发上限、缩批次、退避、预算和停用开关 |
| 多AI改动冲突 | 公共入口和schema反复冲突 | 小契约PR、worktree、模块接线任务和独立审查；不整文件二选一 |
| 技术范围偏离 | 忽略既定目标而不断增加无关工具和框架 | 以六个大任务完整范围持续推进；新增需求单列，既定增强不因复杂自动删减 |
| 报告临近截止才开始 | 没有原始实验和图表来源 | W-072从M0并行推进；每项交付含证据；11月8日前实验正文完整 |
| 演示网络失败 | 模型超时、临时额度不足 | 真实在线与本地降级两套流程；已录制回放明确标注，提供视频备份 |
| 截止时间和模板理解错误 | 文件格式、时区、上传大小不符 | 尽早获取评分/提交清单；11月11日前试包，最后缓冲只修必要问题 |

### 15.4 术语简表

| 术语 | 在本项目中的含义 |
| --- | --- |
| RAG | 先从课程资料检索证据，再让模型依据证据回答 |
| Embedding | 把文本等内容转成可比较的向量，补充同义表达召回 |
| Rerank | 对候选原文重新排序，不负责生成或补造原文 |
| OCR | 从扫描或图片中识别文字；识别结果仍可能有错 |
| Agent工作流 | 按目标组织多步模型、规则和工具操作，并维护状态与边界 |
| MCP | 标准化工具能力的发现与调用；不是模型，也不是向量库 |
