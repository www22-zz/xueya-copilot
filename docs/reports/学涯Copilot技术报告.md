# 学涯 Copilot 技术报告

版本：F 首轮可复现验收稿，2026-10-17。面向课程项目、比赛展示与实际个人学习。软件基线 `main b3d23be`，本轮验证代码及结果位于 `codex/f-quality-delivery`。本稿已有实现与实验正文；真实课程、真实模型效果、人工评审及正式比赛格式仍待补充，不作为最终比赛定稿。

## 摘要

学涯 Copilot 围绕课程资料建立“阅读—问答—知识整理—练习—订正—复习”的个人学习流程。浏览器采用 HTML/CSS/JavaScript，后端采用 Python/FastAPI，以 SQLite 保存课程、学习产物、作业和审计状态。检索、学习 Agent 和 MCP 工具复用同一主平台，模型推理永久通过外部 API 完成，不部署本地模型，不依赖 GPU。生成与保存分开，学习产物先预览、再确认采纳；出处失效和版本冲突阻止旧草稿写入。

本轮在原创验收资料上执行了 190 项 Python 测试、41 项前端测试、四个浏览器检查入口，并新增跨模块学习与备份恢复检查。46 条留出诊断问题中，固定分块与结构分块的纯词法检索全部证据召回分别为 100% 与 92.5%；这说明当前结构分块在部分短问法上存在退化，不能宣称优于基线。本轮无新增付费模型调用，未测得真实模型准确率、OCR 质量或学习成绩提升。

## 1. 背景、目标与范围

学生常在资料阅读、搜索、笔记、刷题和复习之间反复切换，难以追踪答案来自哪里、哪些知识尚未掌握、下一步应复习什么。系统把原件及其结构化证据与学习产物关联，让用户可以从回答回到资料，再将理解转成可练习、可复习的记录。

当前重点是本地运行的个人学习，同时保持课程隔离与后续多课程扩展。核心需求包括文件导入和版本、资料问答与引用、总结和学习包、题目审核与测验、可订正的错因、FSRS 复习、证据支持的知识关系、按时间预算安排计划，以及可取消、可恢复、须确认写入的 Agent 流程。完整协作平台、公开多租户托管和本地模型不属于本轮交付范围。

Open Notebook 作为功能研究参考，启发了资料阅读、来源选择、上下文管理、模板、音频与可迁移课程包的下一轮工作。相关建议及差异已独立记录，未将其功能存在等同于学涯已经实现，见[功能建议](../research/2026-10-17-参考OpenNotebook的学涯功能完善建议.md)与[派工说明](../tasks/下一轮派工与AI执行说明.md)。

## 2. 技术选型与系统架构

| 层次 | 实现与职责 | 选择理由 |
| --- | --- | --- |
| 浏览器 | 原有 HTML/CSS/JavaScript，课程学习空间、生成进度、引用与确认 | 保留既有界面和回归，逐步完善入口 |
| 主服务 | `backend/xueya/server.py`、FastAPI、HTTP/SSE | Python 统一业务和 API 适配，避免双后端重复维护 |
| 平台 | SQLite、资料原件、版本、持久化作业、权限、调用账本 | 本地部署简单，跨模块共享同一事实来源 |
| RAG | 文档解析、结构分块、检索、预算内证据、出处与冲突 | 区分检索命中、位置正确和答案支持性 |
| 学习领域 | `backend/agent/`；`learning_integration.py` 接入主平台 | 保持学习规则独立，复用平台数据库和模型资源 |
| 工具 | MCP 服务、工具注册、审计、预览/确认与取消 | 工具能力有边界，写操作可追踪 |
| 模型 | 外部 API；文本、图像、音频等能力按配置开放 | 本地只做普通业务，不加载推理模型 |

运行路径为：浏览器请求 → 本机主服务鉴权/课程作用域 → 作业或业务服务 → 资料与检索/学习 Agent/MCP → 外部模型网关（按需）→ 带证据的预览 → 用户确认 → 事务保存 → 前端刷新。长任务通过持久化队列执行；进度、停止与失败状态通过既有接口返回。HTTP/SSE 字段约束沿用 [API 契约](../api-contracts.md)。

历史 C 兼容工厂仍用于部分专项测试，但生产始终启动同一主服务，不把旧工厂替换为新的生产平台。具体模块关系见 [B/C 集成说明](../delivery/main-C-integration.md)。

## 3. 资料、数据与接口

资料原件、解析文本、结构片段、文档版本和学习产物分别管理。原件提供回看依据，解析文本用于定位，片段用于检索；引用包含文档、版本及原文位置，不能只凭来源 ID 存在就认定内容支持结论。替换、修正、删除资料会影响快照有效性，旧预览采纳前须重新检查。

学习产物使用独立命名空间，避免与 B 的文档 artifact 冲突。草稿、已采纳记录、作答、诊断订正和复习事件明确区分；确认操作携带操作 ID 与预期版本，重复请求回放原回执，并发修改返回冲突，避免重复保存。课程由服务端作用域绑定，客户端不能通过请求体伪造另一课程的原文或状态。

本地数据库默认在忽略提交的数据目录中。Git 同步代码和迁移，不同步私人 SQLite 文件。整体备份需要数据库与原件保持一致；恢复到新目录后验证内容和版本。本轮新增自动测试实际覆盖了上传、学习产物、订正、复习和备份恢复，未用空数据库“恢复成功”替代有内容恢复。

## 4. RAG 方法

上传通过主平台作业解析 TXT/Markdown、PDF、DOCX 等资料，生成带结构与出处的检索材料。扫描件与媒体需要单独识别能力；没有识别配置时明确报告限制，不能把空文本当作识别成功。

检索支持词法和按配置接入的向量、混合、重排路径；上下文压缩遵守预算，输出引用及资料冲突信息。对话改写可使用历史，但必须保留资料范围。文档更新后重新检查版本，避免继续引用失效资料。当前未配置能力应显示不可用或明确降级，不伪称执行了语义检索。

本轮对照仅衡量纯词法路径：固定 600 字符、重叠 80 字符分块与当前结构分块使用相同问题、相同评分/压缩函数、top-k=6、2000 UTF-8 字节上下文预算。预算是字节而非 token，后续真实模型对照需增加统一 tokenizer 与模型上下文配置。固定基线没有结构服务的数据库及版本校验开销，因此耗时不属于隔离算法变量的严格消融。

## 5. 学习 Agent、MCP 与交互确认

学习流程从所选资料建立证据快照，执行回答、总结、候选题或学习包生成，停在可检查预览，再由用户确认。候选题进入审核，不把模型题目直接作为标准答案。测验记录作答与评分，错因允许用户修正，知识卡片与图谱保留出处，计划考虑可用时间与前置关系。

MCP 将本地学习操作暴露为有定义的工具；Agent 通过工具服务复用业务逻辑，避免自己操作数据库。停止需要传播到模型或工具并释放资源；失败与远端结果不明不能自动当作成功写入。服务重启后恢复检查点，结果不明的远端操作需要检查，避免盲目重复计费或重复写入。

普通问答的无模型路径只返回明确标记的原文摘录；它证明软件降级可用，不证明模型理解正确。真实 Agent 的工具选择质量、步数和总费用仍需通过授权 API 试验单独验证。

## 6. 复习、计划与多模态

系统采用 Python FSRS 保存复习卡及评分后的调度信息。间隔和到期日期是调度输出，不代表已经实测记忆保持率；历史 TypeScript 与当前 Python 库分别版本化，不能声称两者每个日期完全相同。计划将任务排入实际可用时间，记录无法完成的剩余量，不把超预算任务隐藏为“已安排”。

图像识别结果可校正，音频转写和视频输入需要相应能力配置。受控浏览器检查已验证图像、音频和确认流程；视频抽样帧的描述不能宣称等价于理解整段视频或准确的全程时间定位。真实 OCR 的表格/公式保真、噪声音频识别、长视频覆盖及 MiMo 多模态回答质量本轮尚未测量，见[待验证清单](../delivery/F-问题与待验证清单.md)。

## 7. 实验设计与结果

### 7.1 环境、数据和复现

本次运行：Windows，Python 3.13.9，FastAPI 0.143.2、MCP 2.3.0、pypdf 6.20.1、FSRS 6.3.2；依赖以 `requirements.lock` 为准。本地 CPU 执行，无 GPU 推理，无新增付费请求。硬件精确型号、峰值内存、冷启动分位数和生产并发容量尚未系统采集，不能由毫秒级本地检索推出部署容量。

验收集 `F-acceptance-v1` 共 60 条：48 条知识问题（24 个事实各两种问法）、4 条冲突问题、8 条不可答问题。dev 为 14 条，test 为 46 条；按章节分组，成对问法相关。资料与答案由 AI 辅助原创，尚未人工审定，不能称为真实教师黄金集。样例格式、生成命令、切分、指纹与逐题证据见[验收集说明](../../evals/acceptance/README.md)。

样例还包含实际文本 PDF、DOCX 表格、Markdown 代码/公式、图片、无文本层 PDF、长文与注入文本。无文本层 PDF 是几何图形，不用于评价识字质量。长文/注入样本可供专项检查，本轮不能仅凭样本存在就宣称所有长文覆盖和攻击防御均已通过。

### 7.3 检索实际结果

每题三轮温查询，test 46 条中正例 40 条、负例 6 条。结果保存在[逐题 JSON](../../evals/acceptance/results-2026-10-17/results.json)。

| 方法 | 全部证据召回@6 | 摘录召回@6 | MRR@6 | 负例无检索证据 | P50 / P95 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 固定分块 + 词法 | 100.0% | 100.0% | 0.975 | 50.0% | 0.97 / 1.68 |
| 结构分块 + 词法 | 92.5% | 93.18% | 0.875 | 50.0% | 6.97 / 10.39 |

两种方法本次引用字符区间错误均为 0，上下文字节预算超出均为 0。固定分块有 43/46 条诊断通过，结构分块 40/46；该混合计数不是生成答案准确率。

结构分块漏掉“根左右是哪种遍历？”、“左根右是哪种遍历？”和“左右根是哪种遍历？”三种短改写。资料中存在相应先序/中序/后序证据，直接问法能召回，短问法失败，因此应纳入 G4 的检索改写/邻接上下文回归。不能在观察后修改测试题或降低阈值以制造满分。

两种方法对部分“课程指定栈容量上限”“二叉树考试日期”“队列作业截止时间”的问题返回了相关主题段落，但资料没有所问答案。检索召回相关段落并不必然错误；生成器应据此说明未记载。未运行真实生成器，故不能据此计算幻觉率或断言拒答失败。

### 7.4 C 本地规则对照

四个合成计划场景中，固定日预算基线分别超出日预算 33、20、30、0 分钟；考虑实际日可用时间的候选实现均为 0。对照保留同一任务顺序，变量是日历可用时间。完整任务分配、剩余量、选题和五次复习事件见 [C 规则结果](../../evals/acceptance/results-2026-10-17/c-rules-results.json)。

这些小样本说明特定规则约束得到了执行，不证明计划一定提升学习效率，也不证明 FSRS 优于真实用户的其他复习策略。没有随机用户试验，没有长期成绩或记忆保持率数据。

### 7.5 未完成的实验

向量/混合/重排与真实模型对照、人工答案支持度和拒答标注、MiMo 图文及长文质量、OCR/音视频准确率、API 总成本与端到端分位延迟尚未测量。默认 CI 不持有密钥，不执行这类试验。下一次需先确认当次预算、供应商/模型版本、请求上限与失败停止条件，再冻结真实课程留出集、记录账本和人工复核结果。

## 8. 工程可靠性、隐私与交付

本机服务通过鉴权和课程作用域限制读写；写操作经过预览/确认、事务和版本控制；解析与模型请求支持取消；恢复与迁移由统一平台负责。凭据只在本地 `.env`，不放入 Git、报告或样例。报告与 CI 只收集原创样例输出，不打包个人资料目录。

新增 CI 对 PR 和 main 更新执行 Windows/Linux 的 Python 回归、前端单元回归及离线检索诊断，不使用付费模型。真实浏览器检查仍有本机独立入口。工作流是否真正跑完以 GitHub Actions 为准，配置存在不等于远端已通过。

新目录恢复检查已经在自动测试临时目录完成；另一台干净电脑的安装与完整演示仍需人工执行。当前没有完成公开发布许可证审查、正式视频录制或比赛上传。本次交付只包含可复现材料及演示脚本，最终外部提交由项目负责人决定。

## 9. AI 辅助开发与工作分配

AI 用于模块开发、接口接入、原创测试资料与文档草稿。检查以真实命令和可复放结果为依据，不把 AI 自述当成通过证据。模型生成的题目与参考答案仍需人工核对。团队按 G1～G5 整包分工，F 独立维护跨模块验收与报告；共享装配、依赖和数据库由 G1 统一，避免队友整目录覆盖互相冲突。

负责人给队友工作包、分支、任务说明及交付格式；队友将完整执行提示交给 AI，让其先检查现状、逐步实现与验证，提交 PR。失败结果和未配置能力写入进度文件，负责人再决定合并。

## 10. 当前结论与后续改进

当前主平台与 A～E 学习链路能够在受控环境完成操作和持久化，F 已形成独立原创资料、真实诊断、交叉流程回归、报告与演示材料。检索对照揭示短问法召回退化，后续应在保留现有出处与预算约束的前提下改进，并另建未见测试集。真实模型效果、人工审查、成本、性能容量及最终比赛材料仍是明确待办，不能因流程通过而省略。
