## 1. 项目概述

### 1.1 项目背景

大学生在课程学习中通常需要处理大量讲义、PPT、教材、实验指导书和历年试题。传统资料管理方式存在三个问题：

1. 资料分散，查找重点依赖人工翻阅。
2. AI 聊天工具无法提供可靠出处，容易产生幻觉。
3. 学习行为停留在问答，缺少练习、错题回顾和复习安排。

### 1.2 项目定位

**学涯 Copilot** 是一个基于课程知识库的 AI 学习副驾。它将课程资料转化为可检索、可引用、可练习、可规划的学习资产，帮助学生完成从“资料输入”到“能力提升”的闭环。

产品主流程为：

> 上传课程资料 → 建立知识库 → AI 问答 → 查看原文引用 → 保存知识卡片 → 生成练习题 → 生成复习计划

### 1.3 目标用户

- 需要备考和整理课程重点的大学生
- 需要快速检索课程资料的学生
- 希望根据薄弱知识点安排复习计划的学习者

### 1.4 项目目标

- 让 AI 回答具备可追溯的课程资料依据
- 将 RAG 问答与学习练习、复习规划连接起来
- 提供清晰、稳定、适合演示的 Web 产品体验
- 为后续接入真实大模型、向量数据库和用户系统预留扩展接口

## 2. 需求分析

### 2.1 功能需求

| 模块 | 功能 | 优先级 |
|---|---|---|
| 课程空间 | 展示当前课程和学习概览 | P0 |
| 知识库 | 上传 PDF、DOCX、TXT、MD 资料，展示索引状态 | P0 |
| AI 问答 | 根据课程资料回答问题，支持多轮追问 | P0 |
| 引用溯源 | 展示命中来源、页码和原文片段 | P0 |
| 知识卡片 | 将回答或原文保存为重点知识 | P1 |
| 练习系统 | 根据知识点生成练习题并提供答题反馈 | P1 |
| 复习计划 | 根据考试日期和薄弱点安排学习任务 | P1 |
| 状态持久化 | 保存资料记录、知识卡片和学习状态 | P1 |

### 2.2 非功能需求

- **准确性**：回答必须优先使用已上传资料，不将推测内容伪装成事实。
- **可解释性**：回答中的关键结论应关联原文引用。
- **响应性**：核心页面在桌面和移动端均可正常使用。
- **可恢复性**：上传失败、检索为空、AI 服务失败时有明确状态和恢复路径。
- **可扩展性**：前端、检索、生成、业务服务相互解耦。
- **可演示性**：无外部 API Key 时仍可完成完整演示流程。

### 2.3 用户场景

**场景 A：考前复习**

学生上传数据结构讲义和历年试题，询问“二叉搜索树的查找复杂度”，系统返回 O(h)、平衡树 O(log n) 和退化为 O(n) 的解释，并显示讲义和复习题出处。

**场景 B：知识巩固**

学生将回答保存为知识卡片，然后针对“平衡树与旋转”生成练习题，系统根据答题结果把该知识点标记为薄弱点。

**场景 C：复习规划**

学生设置考试日期，系统根据剩余天数、已掌握知识点和错题情况生成未来七天的学习安排。

## 3. 系统架构设计

### 3.1 总体架构

当前交付版本采用“静态 Web 原型 + 本地演示服务层”的架构，生产环境建议升级为前后端分离架构。

```text
┌──────────────────────────────────────────────────────────────┐
│                        Web 前端                               │
│  课程空间 / 知识库 / AI 问答 / 引用查看 / 练习 / 复习计划       │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTP / JSON
┌───────────────────────────▼──────────────────────────────────┐
│                       API 服务层                              │
│  IngestionService / RetrievalService / GenerationService     │
│  PracticeService / PlanService                               │
└───────┬──────────────────┬───────────────────┬───────────────┘
        │                  │                   │
┌───────▼──────┐   ┌───────▼────────┐   ┌─────▼────────────┐
│ 文档解析服务 │   │ 检索与重排服务 │   │ 生成模型服务     │
│ PDF/DOCX/TXT │   │ 向量 + 关键词  │   │ LLM / 规则降级   │
└───────┬──────┘   └───────┬────────┘   └─────┬────────────┘
        │                  │                   │
┌───────▼──────────────────▼───────────────────▼────────────┐
│                     数据与索引层                           │
│ 关系型数据库：课程、用户、对话、学习记录                     │
│ 向量数据库：文档切片、语义向量、引用位置                      │
└──────────────────────────────────────────────────────────┘
```

### 3.2 前端设计

当前原型使用原生 HTML、CSS 和 JavaScript，文件边界为：

- `index.html`：页面结构和可访问的主布局
- `styles.css`：设计令牌、组件样式、响应式布局
- `app.js`：课程状态、检索模拟、引用交互、练习和计划逻辑

前端组件对应关系：

| 组件 | 职责 |
|---|---|
| `CourseSpace` | 课程入口和学习概览 |
| `DocumentUploader` | 资料上传、格式校验和解析状态 |
| `KnowledgeLibrary` | 文档、章节和知识点管理 |
| `ChatWorkspace` | 多轮问答和生成状态 |
| `CitationViewer` | 引用来源和原文抽屉 |
| `KnowledgeCard` | 保存重点知识 |
| `PracticeGenerator` | 生成练习题和答题反馈 |
| `StudyPlanner` | 考试日期和复习任务 |

### 3.3 后端服务设计

生产版建议使用 FastAPI 提供 REST API：

1. `IngestionService`：解析文件、清洗文本、分块、生成向量。
2. `RetrievalService`：向量检索、关键词检索、结果重排、引用片段关联。
3. `GenerationService`：构造上下文、调用大模型、解析结构化回答。
4. `PracticeService`：根据知识点生成题目、批改答案、记录错题。
5. `PlanService`：根据考试日期、错题和掌握度生成复习计划。

## 4. AI 技术方案

### 4.1 技术选型及理由

#### 4.1.1 生成模型

**推荐方案**：支持 OpenAI-compatible 接口的中文友好大模型，例如 Qwen-Plus、GLM-4-Flash 或 GPT-4o-mini。

选型理由：

- 能够理解中文课程内容和复杂问题
- 支持结构化输出，方便返回答案、引用和知识点
- 可通过统一接口替换模型，降低供应商锁定
- 可根据成本在演示、校内部署和生产环境选择不同档位

#### 4.1.2 Embedding 模型

**推荐方案**：BGE-M3 或同等中文语义向量模型。

选型理由：

- 对中文课程文本具有较好语义表达能力
- 支持较长文本，减少切片数量
- 可同时服务中文讲义、术语和代码注释
- 可本地部署，适合校园内网和隐私要求较高的场景

#### 4.1.3 向量数据库

- **开发/比赛演示**：Chroma，部署轻量、接口简单
- **生产环境**：PostgreSQL + pgvector，便于与业务数据统一管理

#### 4.1.4 检索策略

采用“向量检索 + 关键词检索 + 重排”的混合 RAG：

1. 对问题进行向量化。
2. 在当前课程范围内进行向量近邻检索。
3. 使用 BM25 或关键词匹配补充精确术语命中。
4. 合并结果并去重。
5. 使用重排模型或规则评分筛选 top-k 片段。
6. 将片段、文档名、页码和原文位置传递给生成模型。

### 4.2 当前原型中的 AI 集成方式

当前版本为了保证无 API Key 时也能演示，使用了**本地检索器 + 规则化生成器**作为降级方案：

1. 从问题中提取关键词。
2. 对课程资料片段进行关键词相关性评分。
3. 返回 top 片段及引用。
4. 根据命中主题生成基于片段的回答。
5. 如果没有命中，明确返回“资料中未找到”，不编造答案。

核心逻辑位于 `app.js` 的 `retrieve()` 和 `answerFor()`：

- `retrieve()`：根据关键词计算来源相关性。
- `answerFor()`：基于命中来源生成带引用回答。
- `aiBodyMarkup()`：渲染引用按钮和答案操作。

生产版只需将 `answerFor()` 替换为大模型 API 调用，并保留相同的数据结构：

```json
{
  "answer": "回答文本",
  "sources": ["source-1", "source-2"],
  "confidence": 0.91,
  "knowledgePoints": ["二叉搜索树", "查找复杂度"]
}
```

### 4.3 提示词设计

系统提示词需要约束模型：

- 只能使用提供的课程资料回答
- 关键结论必须关联来源
- 资料不足时明确说明，不推测
- 使用学生能理解的中文解释
- 将公式、复杂度和术语准确表达

用户提示词结构：

```text
课程：数据结构
历史对话：...
检索片段：...
用户问题：...
输出要求：答案 + 引用编号 + 知识点
```

### 4.4 优化策略

1. **分块优化**：按章节、段落和标题切分，避免把公式和上下文切断。
2. **混合检索**：向量检索抓语义，关键词检索抓术语。
3. **重排优化**：对候选片段二次评分，提高 top-k 准确率。
4. **引用约束**：要求生成模型使用 `[1]`、`[2]` 等编号，并由后端绑定真实来源。
5. **上下文压缩**：只传入相关片段，减少 Token 成本和干扰。
6. **缓存优化**：缓存高频问题的回答和 Embedding 结果。
7. **降级策略**：外部模型超时或不可用时，切换到本地演示生成器。
8. **评估优化**：建立问答准确率、引用命中率和无答案识别率评估集。

## 5. 核心功能实现

### 5.1 课程学习总览

页面展示课程进度、资料数量、引用数量、知识卡片数量和今日练习。用户可以从总览快速进入问答、知识库和练习模块。

### 5.2 课程知识库与上传

支持 PDF、DOCX、TXT、MD 文件：

- 上传前进行扩展名校验
- 一次可选择多个文件
- 每个文件独立显示解析状态
- 解析成功后加入资料列表
- 资料列表保存在浏览器 `localStorage`

### 5.3 AI 问答与多轮追问

用户输入问题后：

1. 插入用户消息。
2. 显示“正在检索课程知识库并整理证据”。
3. 执行本地检索或调用生产 RAG API。
4. 显示回答、引用编号和置信状态。
5. 支持保存知识卡片和继续追问。

### 5.4 引用溯源

回答中的引用编号可点击，右侧抽屉显示：

- 文档名称
- 章节和页码
- 原文片段
- 该来源与当前回答的关系

引用数据结构包含 `sourceId`、`documentId`、`pageNumber` 和 `quote`，生产版可扩展为原文字符偏移量。

### 5.5 知识卡片

点击“保存为知识卡片”后：

- 知识卡片数量更新
- 保存记录写入 `localStorage`
- 后续可扩展为与来源绑定的结构化知识卡片

### 5.6 练习与错题

系统提供选择题、答案反馈和错题列表。当前原型内置“树与二叉树”主题练习题，生产版可由 `PracticeService` 根据知识卡片和错题记录动态生成题目。

### 5.7 复习计划

用户可以设置考试日期，系统显示剩余天数和学习任务。当前原型提供七天学习时间线，生产版可根据以下因素动态排程：

- 考试时间
- 知识点掌握度
- 错题数量
- 每日预计学习时间
- 已完成任务

## 7. 创新点说明

### 7.1 技术创新点

1. **证据优先的 RAG 设计**：回答、引用、原文定位形成可验证链路，降低大模型幻觉风险。
2. **混合检索策略**：向量语义检索与关键词精确检索结合，兼顾概念理解和术语命中。
3. **可降级 AI 架构**：外部模型不可用时仍可使用本地演示服务完成核心流程。
4. **回答结构化输出**：统一返回答案、来源、知识点和置信状态，便于前后端解耦。
5. **学习数据闭环**：问答结果可以转化为知识卡片、练习题和复习任务。

### 7.2 应用创新点

1. **从“问答工具”升级为“学习副驾”**：覆盖理解、巩固、练习和复习四个阶段。
2. **引用驱动学习**：学生不仅得到答案，还能回到课程原文验证答案。
3. **薄弱点导向复习**：错题和知识点掌握度直接影响学习计划。
4. **课程知识资产化**：上传的讲义、试题和实验资料变成可持续检索的个人知识库。
5. **适合真实学习场景**：围绕大学生备考、课程复习和知识整理，而不是做一个泛化聊天机器人。

## 8. 总结与展望

### 8.1 项目总结

学涯 Copilot 将课程资料、RAG 问答、原文引用、知识卡片、练习题和复习计划整合为一个完整的学习产品。当前版本已经完成可运行的 Web 原型，具备清晰的信息架构、响应式布局、来源抽屉、资料上传、练习反馈和本地状态持久化。

在 AI 方面，项目采用“生产级 RAG 目标架构 + 本地可演示降级方案”的策略，既保证比赛现场演示的稳定性，也为接入真实大模型和向量数据库预留了接口。

### 8.2 后续展望

1. 接入真实 Embedding、向量数据库和大模型 API。
2. 支持 PDF OCR、PPT 图片和多模态课程资料解析。
3. 增加基于错题的自适应学习路径。
4. 支持教师端课程管理、班级知识库和学习报告。
5. 增加引用高亮、原文字符级定位和答案可信度评估。
6. 引入用户账号、云端同步和多设备学习记录。
7. 建立 RAG 评估集，对回答准确率和引用质量持续跟踪。
