# 参考 Open Notebook 的学涯 Copilot 功能完善建议

> 日期：2026-10-17。学涯基线：`main / a4c6258`。本文是功能建议，不代表已实现、已排期或已通过真实 API 验收。此次只新增文档，不修改应用代码、数据库、配置或原任务单。
>
> Open Notebook 核对版本：[`a0f6f3081ae06328f0a451b3a3ef2959ca25721d`](https://github.com/lfnovo/open-notebook/tree/a0f6f3081ae06328f0a451b3a3ef2959ca25721d)。已阅读官方功能文档，并浅克隆检查资料/笔记领域、上下文构建、Transformation 和 Ask 工作流。没有安装运行该项目，没有据此推断真实模型准确率、性能或中文课程适配效果。

## 一、先看结论：最值得做什么

**建议把学涯完善成“能看资料、能整理理解、能检验学习结果”的一体化课程工作台。** Open Notebook 的内容组织与研究体验值得借鉴；学涯继续以测验、错因订正、FSRS 和学习计划形成自己的学习特色。

优先推进这六件事：

1. **统一现有学习入口**：把旧页面与进阶区里重复、分散的操作合成一套主流程。
2. **做模型与能力设置中心**：用户能看懂哪些服务已配置、哪些需要配置，以及一次任务会调用什么。
3. **让资料范围与上下文可控**：明确选择检索、整章精读、背景摘要，保存每个会话的选择。
4. **做学习加工模板库**：把总结、概念整理、例题讲解等变成可复用、可追溯的课程处理任务。
5. **让资料、笔记、题目都能被统一检索**：从“搜索文件名”提升为“找到学过的内容和原文依据”。
6. **增加面向复习的音频课程**：从现有朗读扩展为“讲解—提问—暂停回忆—核对”的学习音频。

**先读本节和第六节，就能分配大任务；承担任务的 AI 再阅读第四、第五节的细项和验收要求。**

### 需要有选择地借鉴

- **引用粒度应保留学涯现有设计。** 参考项目的文档说明，引用指向整份资料、笔记或洞察，并不自带页码与高亮位置。学涯已有片段、页/偏移和版本校验，应继续完善这些能力，而不是退回整份资料引用。[引用说明](https://github.com/lfnovo/open-notebook/blob/a0f6f3081ae06328f0a451b3a3ef2959ca25721d/docs/3-USER-GUIDE/citations.md)
- **不能把有 API 当成页面已可用。** 参考项目的笔记文档注明，洞察转笔记已有 API，但尚无对应 UI 按钮。学涯后续每项都要同时验收服务、入口、状态、保存和恢复。[笔记说明](https://github.com/lfnovo/open-notebook/blob/a0f6f3081ae06328f0a451b3a3ef2959ca25721d/docs/3-USER-GUIDE/working-with-notes.md)
- **上下文选择应按会话持久化。** 参考项目文档描述其上下文选择在刷新后恢复默认值；学涯已有按会话保存资料范围的基础，应在此基础上扩展，不引入选择丢失的问题。[会话说明](https://github.com/lfnovo/open-notebook/blob/a0f6f3081ae06328f0a451b3a3ef2959ca25721d/docs/3-USER-GUIDE/chat-effectively.md)
- **产品定位不同。** 参考项目定位研究资料管理；学涯面向课程学习。本次建议把内容组织经验转成学习活动，不据此宣称它没有测验等其他功能，也不以其文档列表推断完整功能边界。[产品定位](https://github.com/lfnovo/open-notebook/blob/a0f6f3081ae06328f0a451b3a3ef2959ca25721d/VISION.md)

## 四、具体功能建议

### ON-01：统一课程学习工作台

**现状与问题：** 原页面和进阶区域已可操作，但部分同类功能分散，用户难判断该点哪个入口。

**建议：** 桌面端围绕“资料/目录—原文与学习成果—对话与操作”组织工作区；手机用资料、阅读、学习三个可切换视图。沿用现有视觉和 HTML/CSS/JS，不为模仿参考项目更换前端框架。

**内部工作：** 梳理重复按钮；统一课程/资料选择；将总结、出题、保存笔记、复习等动作放到当前内容旁；保留旧记录查看与迁移；一个任务使用一套进度和停止入口。

**验收：** 从打开一份讲义到核对回答、保存笔记和进入测验，不需要用户知道“旧功能”“进阶功能”的区别；刷新、课程切换和手机使用保留正确状态。

**主责：** A；C/E 配合。建议第一批。

### ON-02：模型与能力设置中心

**现状与问题：** 配置主要在 `.env`；“MiMo 已配置”不能说明 OCR、向量、语音等每项都能用。

**建议：** 提供“服务连接—能力状态—默认用途—用量”四部分。默认仍使用 MiMo；按文字/图像、Embedding、Rerank、OCR、ASR、TTS 分配兼容适配器，不要求一个模型承担所有任务。

**内部工作：** 显示未配置、仅有配置、连接已验证、测试失败等状态；保留 `.env` 优先级；支持不泄露密钥的更换/移除；显式区分免费本地检查与可能收费的测试；不自动下载模型或切换付费供应商。若提供页面保存凭据，仍只由后端保管，并先设计本机凭据保护、恢复和备份策略。

**验收：** 未配置向量服务时明确保留词法检索；用户能从失败提示直接找到相关设置；任何密钥都不出现在页面回显、日志、导出和 Git 中；每种能力分别记录实际验证结果。

**主责：** E；A/B/C/F 配合。建议第一批。

### ON-03：可解释、可保存的上下文选择

**现状与问题：** 已有资料范围，但缺少对“检索到的片段”“整章原文”“摘要/笔记”的清晰说明。

**建议：** 用户可以选择“相关片段回答”“选定章节精读”“一般知识交流”。逐份资料可设不使用、作为背景摘要、使用原文；个人笔记单独勾选。默认模式保持轻量，不把整门课每轮都发送出去。

**内部工作：** 展示本轮使用的资料/版本、范围和大致输入用量；明确是否省略、分段或只作背景；按课程和会话保存选择；长历史生成可核对的会话摘要，仍保留原对话。没有可靠 tokenizer 时标为粗略估计，不冒充精确 token 或账单。

**验收：** 用户排除某份资料后，新回答不再使用它；刷新不丢选择；摘要只做导航，重要断言回到原文证据；超预算时让用户缩小范围或显式选择分段任务，不静默丢掉后半章。

**主责：** A/C；B/E 配合。建议第一批，与 ON-01 一起做。

### ON-04：统一资料导入向导

**现状与问题：** 文件上传较完整，但从公开网页、课堂临时文字和链接进入课程的路径不足。

**建议：** 保留现有上传，增加“网页链接”“粘贴文字”；图片、音视频继续复用已有媒体服务。每次导入允许选择所属课程/章节、处理方式、是否建立向量索引，以及是否运行学习模板。

**内部工作：** 网页保存提取时间、原 URL、正文快照和内容 hash；刷新网页创建可比较的新版本；同批资料逐项显示成功/失败；普通解析与收费处理分开确认。网址抓取由后端执行，限制协议、重定向、内网地址、大小与耗时；登录页面和不可访问页面明确失败，不索取浏览器密码。

**验收：** 本地课件、公开文章、课堂文字进入同一课程并能引用；网页后来变化时旧笔记仍能找到当时快照；解析成功但摘要失败时保留有效资料，允许单独继续处理。

**主责：** B/E；A/C 配合。建议第一至第二批。

### ON-05：课程章节与资料复用

**现状与问题：** 已有多课程与章节元数据，但“学到哪一章、哪些材料属于同一课次”的组织还可加强。

**建议：** 在课程内建立章/节或课次集合，集中展示该章的资料、概念、总结、练习、错题与复习安排。公共资料可显式添加到另一课程，减少重复操作。

**内部工作：** 课程描述、目标、先修要求与考试范围进入课程设置；提供资料移动、关联、归档与恢复；区分“移出本章”“移出本课程”和“删除资料”。复用原件时可以共享不可变文件 hash，但课程记录、来源 ID、授权、索引与学习数据继续隔离。

**验收：** 同一资料在两门课程使用时，删除或归档其中一门不破坏另一门；不会借共享原件绕过课程范围校验；旧课程无需强制迁移到新目录结构。

**主责：** E/B；A/C 配合。建议第二批。

### ON-06：课程学习加工模板库

**现状与问题：** C 已能总结、对照和生成学习包，缺的是统一的模板管理、组合与复用体验。

**建议：** 将已有能力封装成有版本的模板：章节导读、概念/公式表、例题步骤讲解、易混淆概念对照、自我解释问题、考前提纲、文献阅读笔记。模板按科目可编辑，但不改变可信证据和确认写入规则。

**内部工作：** 模板保存目标、适用资料、输入范围、输出格式、模型用途、提示词版本及产物关联；提供试运行；支持单份资料与整章批处理；批处理逐项记录，避免一次失败全部重做。模板输出进入现有学习产物层，不创建第二套成果数据库。

**验收：** 生成结果显示资料版本和模板版本；用户编辑过的笔记不会被再次运行覆盖；无正文、输出截断或格式不合法时不标记完成；可预览并选择是否转成笔记、候选题或复习卡。

**主责：** C；A/E/D 配合。建议第二批。

### ON-07：统一内容搜索

**现状与问题：** 当前快捷搜索主要查页面、资料名称与卡片标题；B 的正文检索还没有覆盖全部学习对象的统一搜索体验。

**建议：** 一个搜索框查课程资料正文、笔记、学习产物、候选/已审核题、错题及概念；按课程、章节、内容类型、时间和有效版本筛选。搜索结果与“请 AI 综合回答”明确分开。

**内部工作：** 先让无需模型的文本搜索可用，再接已配置的语义/混合检索；为笔记、题目等建立独立类型索引与更新机制；结果显示命中片段、内容类型和位置；支持快捷键及跳转原文。

**验收：** 能用正文中的句子找到一份标题无关的讲义；能找回自己的某条解释和一道错题；无向量服务时不假称语义搜索；其他课程和已删除资料不会混入限定范围。

**主责：** B；A/C/E 配合。建议第二批。

### ON-08：有边界的多步骤综合问答

**现状与问题：** 已有主聊天、B 检索和 C 章节流程，跨资料复杂问题还可提高覆盖与过程说明。

**建议：** 对复杂问题提供“拆成子问题—分范围检索—整理证据—综合回答”。例如“比较本课程三种树结构的适用场景，并说明我容易混淆哪里”。简单问题仍走当前轻量路径。

**内部工作：** 复用 B 检索、D 工具、E 队列/账本和 C 的产物确认；设置查询数、步数、并发及费用预算；展示查询词、已核对资料、缺少的证据与简短过程摘要，不要求输出模型隐藏推理。先支持当前课程；跨课程必须显式选择并逐课程检查范围。

**验收：** 每项比较结论有对应原文；不可答部分明确说明；停止、重启、来源更新和未知远端结果都可解释；向量未配置时可明确使用词法路线，不以空的向量结果冒充“课程没有资料”。

**主责：** C/B；D/E/A 配合。建议第二至第三批，先完成 ON-02、ON-03、ON-07。

### ON-09：笔记成为可继续学习的内容

**现状与问题：** 笔记能保存、编辑、恢复，但浏览器笔记与服务端产物并存，后续使用和出处表达还可统一。

**建议：** 支持从回答、总结、原文摘录转成同一种可编辑学习笔记，带资料链接、生成/人工来源和版本。笔记可用于搜索、复习讲解或候选练习，但不自动当成权威原文。

**内部工作：** 标记原文摘录、AI 生成、人工撰写、人工修订；支持“我的理解—原文依据—待确认问题”；保留修改历史和版本关系；关联概念、题目、复习卡与学习任务；让旧笔记有可预览的兼容导入路径。

**验收：** 笔记中的错误不会被重新检索包装成教材结论；生成问题时能区分依据来自教材还是个人假设；改笔记不静默改变已作答题目和历史评分。

**主责：** A/C/E；B 配合。建议第二批。

### ON-10：来源变化与学习成果依赖检查

**现状与问题：** 已有版本与过期证据阻止写入，用户还需要看到“哪份成果受到了资料变化影响”。

**建议：** 为资料→总结/笔记→题目/图谱/卡片→计划建立可查询的依赖关系。资料纠错、替换或删除后，展示受影响内容，允许保留历史、重新核对或生成新版本。

**内部工作：** 记录来源版本、模板版本、人工修订和采纳记录；集中展示待核对项；分清原文过期、模型配置变化和单纯索引重建；重建索引不应无理由使原文事实失效。

**验收：** 修改教材中的一个定义后，相关候选题能提示复核；已保存旧答卷和旧证据仍可追溯；不会自动重跑全部付费任务，也不会覆盖人工修订。

**主责：** E/C/B；A/F 配合。建议第二批，作为可靠性增强。

### ON-11：把音视频纳入课程资料生命周期

**现状与问题：** 已有图像识别、音频转写和三处视频抽帧；媒体结果与章节学习的联系仍可增强。

**建议：** 录音、截图、课件和课程视频可以放进同一课次。转写按真实片段形成章节，问题和笔记可跳回对应媒体位置；支持“这段讲解对应课件哪一页”的人工确认关联。

**内部工作：** 媒体与文本分段统一版本；支持较长录音的显式分段后台任务；播放器定位、识别纠错、片段总结和资料关联；视频抽帧数量与范围由用户选择，并展示实际覆盖情况。

**验收：** 点击引用能回到真实片段；无逐字对齐信息时只显示片段时间；仅识别三个画面时不声称理解完整视频；没有 ASR/OCR 等服务时仍可保存原件并明确待处理状态。

**主责：** C/B；A/E 配合。建议第二至第三批。

### ON-12：面向记忆和理解的复习音频

**现状与问题：** 已有 TTS；直接朗读总结还不足以形成有教学结构的学习内容。

**建议：** 首先做单人讲解与双人问答两种格式：重点导入、概念解释、易错点、回忆问题、留白、参考讲解和复习提示。可按今日薄弱点、某章或已核对笔记生成，不追求先堆很多角色。

**内部工作：** 先生成可编辑脚本并显示出处，用户确认后再合成；支持段落导航、字幕/文本稿、播放进度与下载；将回忆问题关联现有题库或复习卡；保存声音、资料和脚本版本。先用供应商已有音色，不把声音克隆作为依赖。

**验收：** 内容能回到课程原文；脚本修改后只处理受影响的音频段；停止或未知结果不自动重放收费请求；听完不会自动增加掌握度，只有实际作答或明确自评产生学习事件。

**主责：** C；A/E/F 配合。建议第三批，完成真实 TTS/ASR 验收后推进。

### ON-13：统一任务、用量和失败处理中心

**现状与问题：** 已有持久化作业、运行记录和 API 账本，但后台任务藏在不同入口，用户难判断等待、失败或结果不明。

**建议：** 在课程内显示进行中任务、待确认结果、需人工处理的失败，以及本次任务的服务调用与实际 usage；同时保留全局任务入口。

**内部工作：** 统一解析、OCR、索引、学习包、音频等任务展示；标明步骤和部分成功；区分停止等待与取消后台执行；明确哪些可以安全重试；提供进入原始资料/产物/设置的操作。金额只有可靠价目和实际计费单位齐全时才估算，并注明非账单。

**验收：** 关闭网页再回来能找到任务和产物；不会因刷新重复收费；未知远端结果不出现自动重试；失败原因有可操作的说明，同时不泄露私人正文或密钥。

**主责：** E/A；B/C/D/F 配合。建议第一批，与 ON-02 同包交付。

### ON-14：课程学习包导出与安全复用

**现状与问题：** 已有导出、数据库/原件备份恢复，但日常“拿走这一章成果”与完整系统备份的需求不同。

**建议：** 导出 Markdown 笔记、含原文出处的章节学习包、题目与解释清单、复习卡数据、音频及脚本。区分“我的完整备份”和“用于展示/分享的副本”，先做文件交付，不默认扩成云协作。

**内部工作：** 包内带版本清单、附件和可恢复 ID 映射；导出前选择是否包含原件、答案、个人成绩及对话；支持预览导入为新课程或合入已有课程，并核对重复项与冲突；不把数据库原始文件直接当共享资料包。

**验收：** 在新临时目录导入后，笔记、原文引用与附件可解析；不携带 API key、停止令牌或不相关私人课程；文件包的导入不会覆盖他人的数据或自动共享数据库。

**主责：** E/F；A/B/C 配合。建议第二至第三批。

## 五、学涯应该重点加强自己的学习闭环

以下是结合学涯定位提出的设计，不是声称 Open Notebook 已提供这些学习能力。

建议把每项内容加工都导向可检查的学习活动：

```text
导入一章资料 → 确认范围与来源 → 生成导读/概念/例题
    → 用自己的话解释 → 审核并完成小测 → 核对错因
    → 采纳复习卡与计划 → 回忆练习/复习音频 → 再次作答
```

| 现有学习能力 | 建议增强的连接 | 必须避免的误判 |
| --- | --- | --- |
| 章节学习包 | 读取同章资料、已审核题目、已有笔记和实际薄弱点，显示未覆盖部分 | 有了总结就等于学完一章 |
| 错因订正 | 错题直接跳到原文、相关概念和一题变式，订正后再次检查 | 模型给出的错因一定正确 |
| FSRS 与计划 | 今日安排能回到具体卡片/题目，学习结束后写入真实反馈 | 播放完音频或点击“完成”就等于掌握 |
| 图谱与先修路径 | 图节点进入例题、来源、练习和掌握证据；关系可人工修正 | 自动生成的关系都是先修关系 |
| 多模态诊断 | 识别先核对，再分析步骤；错误文字不进入学习证据 | 识别结果天然可靠 |
| 学习推荐 | 说明来自哪次作答、哪张卡、哪份资料和哪个目标 | 一次作答就能给出精确能力结论 |

如果需要竞赛展示，建议展示一条真实完整流程，并记录原文引用正确性、任务恢复、用量和真实作答变化。长期学习收益仍需专门研究，不以软件流程通过代替学习效果证明。

## 七、实现时沿用什么，不照搬什么

- **保持已有技术边界**：前端继续 HTML/CSS/JS，后端 Python/FastAPI，默认 SQLite 与现有文件仓库；参考项目使用的数据库、前端框架或工作流库不是学涯必须迁移的理由。
- **保持 API-only 决定**：不引入 Ollama、本地大模型、CUDA、GPU 调度或本地语音模型；参考项目支持本地模型不改变学涯既定约束。
- **保持学习定位**：不把通用聊天、任意工具执行、多人账号或教师平台当作本轮依赖；以后正式纳入需求再设计。
- **保持真实来源**：教材原文、网页快照、人工笔记和 AI 产物分类型。跨对象检索可以合并展示，证据等级不能混为一谈。
- **保持当前可靠性规则**：后台写入需要预览/明确采纳，远端结果不明不能盲目重试，取消等待与取消执行要区分。
- **借鉴思想后独立适配**：此次未复制外部代码。若后续复用源码，先核对对应版本的许可证、依赖和接口适配，并保留项目要求的署名；报告说明哪些是借鉴，哪些是学涯自己的实现与实验。
