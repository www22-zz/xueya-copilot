# 练习模块重构需求说明：三入口、原始算法 Hot100 与 408 考研题库

日期：2026-10-29　版本：1.0　用途：交给后续模型实施的需求说明

本文记录已与用户确认的产品要求。本文档交付不表示功能已实现。实施时以“本期范围”为准，不把后续设想提前做成本期功能。

## 1. 已确认的决定与本期边界

| 项目 | 已确认要求 |
| --- | --- |
| 内容范围 | 仅此次重做的练习模块面向计算机知识；不把整个网站、问答或资料库强制限制为计算机内容。 |
| 页面结构 | 练习首页提供三个独立入口：右上算法 Hot100；向下滚动后，左侧资料练习100题、右侧408考研题库，两张卡片对称排列。 |
| 右上算法入口 | 复用项目一开始已有的完整力扣算法 Hot100，预置100道代码题，与上传资料无关。 |
| 左下资料入口 | **本期仅完成入口及承接页**。具体资料接入方式尚未确定，不实施新的上传、解析联动或自动出题。 |
| 左下后续方向 | 同一科目上传的资料合并，生成一套100题；上传后自动触发；题型为单选、多选、判断、填空。此方向已确认，但接入流程暂缓实现。 |
| 右下考研入口 | **本期实际提供408考研题库，不能只做入口或空占位**。需主动检索历年资料并整理题目。 |
| 考研题量与题型 | 首版300道：240道单项选择题、60道综合应用题；后续可以扩充。综合题按一道完整大题计数，小问不拆开凑数量。 |
| 考研范围与来源 | 数据结构、计算机组成原理、操作系统、计算机网络；预先整理固定题库，以可核对出处的历年真题为主，不足处用原创模拟题补充。 |
| 算法作答方式 | 沿用看题、提示、参考题解和跳转力扣写代码的方式，保留进度与笔记；不新增网站内编辑器、代码运行或在线判题。 |
| 408综合题评价 | 按小问保存答案及过程，对照参考解答和评分点自评；不依赖AI评分。 |

**范围解释：只有左下先做入口。右上需要恢复可用的原算法100题，右下需要交付真实可练的300题。不能把三个入口都交付为空卡片。**

## 2. 页面布局与导航

### 2.1 练习首页

顶部导航进入“练习”时，首先看到三入口首页，而不是直接进入旧的某一套题库。

桌面端关系示意：

```text
┌──────────────────────────────────────────────────────────────┐
│ 左上：练习引导文案                 右上：力扣算法 Hot100       │
│ 说明三种练习的用途                 预置100道经典算法题         │
│                                  [进入算法练习]              │
└──────────────────────────────────────────────────────────────┘
                         向下滚动
┌──────────────────────────────┐  ┌────────────────────────────┐
│ 左下：资料练习100题           │  │ 右下：408考研题库           │
│ 同一科目资料的专项巩固        │  │ 240单选＋60综合应用         │
│ 本期入口可进入，接入待准备    │  │ 固定300题，真题为主         │
│ [查看资料练习]               │  │ [进入408练习]              │
└──────────────────────────────┘  └────────────────────────────┘
```

布局要求：

- 保留“顶部引导＋右上算法入口、下方两张对称入口”的层次，不改为三个并排标签或三个等宽卡片。
- 左下、右下卡片在桌面端宽度和视觉重量一致，按钮和主要信息位置对应。
- 允许自然滚动，不依靠大面积空白强行制造第二屏。
- 手机端依次排列引导、算法入口、资料入口、考研入口；内容不横向溢出。
- 延续项目现有深浅主题、圆角、文字对比度、键盘操作及自定义鼠标体验；滚动时标题和卡片不重叠。

引导文案可采用类似“从经典算法、课程巩固到408备考，选择适合你的练习”的表达。文案可润色，但三个入口的用途必须一眼可区分。

### 2.2 进入与返回

- 每个入口进入各自的练习页或承接页；提供明确的“返回练习首页”。
- 算法与408入口有真实内容，不能只是按钮跳到空白页。
- 资料入口本期也应可进入，展示用途、计划题型与“资料接入准备中”，不是无响应按钮。
- 返回首页再进入时，保留原来题库的筛选、选中题目、练习进度和笔记。
- 具体路由命名可由实现者确定；已有深链接需要兼容或明确转接，不能让旧错题与历史报告失去目标。

## 3. 右上：复用原始力扣算法 Hot100

### 3.1 题库身份

这个入口只表示原始的100道算法编程题。它不表示后来教材新编的混合题型Hot100，也不表示上传资料后生成的所谓热门100题。

- 初次进入即有100题，不要求先上传任何资料，不调用模型临时生成。
- 换课程、新增资料或启用其他题库，不能替换这100题。
- 复用原有题目、编号、主题、难度、提示、示例、解析、题解和力扣原题链接。
- 保留已有Python、C++、Java参考题解以及时空复杂度、易错点。
- 保留按知识点/难度筛选、查看提示与题解、顺序/随机练习、待刷/掌握/错题状态和随手记等已有能力。
- 写代码与实际判题继续通过力扣原题链接完成；本期不增加编译运行平台。

### 3.2 已核对的可复用数据

以下路径均相对仓库根目录：

- `backend/xueya/data/practice_bank.json`：原始固定库共250题，其中`category=hot100`的100题为所需算法题。其余旧基础100题、面试50题不能混入此入口。
- `backend/xueya/data/hot100_official.json`：原始题单快照，记录核对日期2026-10-25及力扣来源。复用现有清单，不宣称本次重新核实了线上实时热度。
- 100题的原ID由81个`h100-*`和19个`lc-*`组成，必须保留；不要重编号造成笔记和进度断链。
- 原始100题按17个主题分组；主题与数据应直接复用，不必重新编写一套相似题。

## 4. 左下：资料练习100题，本期只完成入口

### 4.1 本期应交付

- 完整的入口卡片、按钮及可返回的承接页。
- 明确说明未来面向当前科目的资料巩固，目标100题，四种题型为单选、多选、判断、填空。
- 展示诚实的准备状态，例如“资料接入准备中”，不能写“100题已就绪”。
- 不要求用户现在决定或完成一种尚未确认的上传流程。
- 不展示虚构题目、随机示例或旧200题，冒充已经根据当前资料生成的100题。

### 4.2 已确认、留给后续阶段的规则

1. 用户上传的是同一个科目的资料，应合并该科目的资料生成**一套100题**，不是每个文件各出100题。
2. 未来接入后，上传完成并满足解析条件时自动触发，不要求每次手动选择文件再点“生成”。
3. 资料题只采用单选、多选、判断、填空；算法代码题已有独立入口，本资料入口不额外混入代码题。
4. 科目、章节、知识点分类应与资料内容一致；不能把所有资料统一写成一个“资料重点”分类。

目前暂缓：具体上传入口、文件组织与导入方式、多份资料如何确认齐备、追加资料后何时更新题库、生成批次/首批数量、失败续做和具体模型出题实现。后续另行确定，不能由本期实施模型自行补成一套完整上传业务。

### 4.3 旧流程的处理

现有项目已经存在“上传一份资料，自动生成Hot100＋基础100”的旧功能。它与本次新定义不一致。

- 本期练习入口不得再把旧功能作为默认入口宣传或自动启动。
- “资料入口尚未接入”不能与“后台仍在自动生成旧200题”同时存在。需阻止旧练习出题流程新增调用及后续续批，不能只隐藏按钮。
- 检查上传钩子、解析回调、已有监听记录、排队任务、重启恢复、续做和每批完成后的再排队；旧请求已在途时保留真实结果与用量，随后不再自动续批。
- 不全局关闭模型或资料解析，不影响问答、OCR等其他模块的原有用途。
- 原有题库和个人练习记录保留为历史数据，不清空数据库或浏览器存储。

## 5. 右下：实际整理并提供408考研300题

### 5.1 必须有真实题库

实现者需要主动查找历年408资料，筛选、核对、整理并预置300题；不能把这项工作留成“后续补题”，也不能让用户先上传考研资料才能使用。

- 首次使用即能进入固定题库练习，与个人上传资料和当前课程无关。
- 固定300题：240单选、60综合应用，后续可扩充。
- 页面名称采用“408考研题库”等可扩展名称，不再称“考研100题”。
- 不在每次打开、刷新或切换课程时调用模型重生成。
- 题目以有出处的历年真题为主；选题仍不足或知识点有缺口时，允许用经过核对的原创模拟题补充。
- 原创、改编、真题分别标注。原创建议由实现者在整理阶段完成，不把资料缺口转成运行时持续调用模型的任务。

### 5.2 科目与知识点

必须覆盖四科：

| 科目 | 重点覆盖示例 |
| --- | --- |
| 数据结构 | 线性表、栈队列、树、图、查找、排序、复杂度及算法分析。 |
| 计算机组成原理 | 数据表示与运算、存储层次与Cache、指令、CPU、流水线、输入输出。 |
| 操作系统 | 进程线程、调度、同步互斥、死锁、内存、虚拟存储、文件和输入输出管理。 |
| 计算机网络 | 体系结构、链路层、网络层、IP与路由、传输层、TCP/UDP及应用层。 |

每题具有科目、章节/主题和具体知识点，不以全部标成“考研重点”代替分类。支持按科目、知识点、题型和难度筛选，题目来源也应可辨认。

选题配额可参考下表，**这是实施建议，不是用户指定或官方考试题量**：

| 科目 | 建议单选 | 建议综合 | 合计 |
| --- | ---: | ---: | ---: |
| 数据结构 | 72 | 18 | 90 |
| 计算机组成原理 | 72 | 18 | 90 |
| 操作系统 | 56 | 14 | 70 |
| 计算机网络 | 40 | 10 | 50 |
| 总计 | 240 | 60 | 300 |

可按资料可核实性和知识覆盖调整科目内分配，但总量240＋60及四科覆盖不变，不能为了配额编造真题。

### 5.3 历年资料收集与真实性

- 查找跨年份的408真题资料，保留逐题来源索引；优先核对原卷或高校、出版社等可追溯公开资料。
- 每道真题记录考试名称、年份、原题号、题型、来源链接/出版信息及页码或其他定位信息。
- 参考答案与解析也要有核对依据；高校整理版、出版社解析、自编解析不能直接标为“教育考试院官方答案”。
- 原题有图、表、条件或多小问时，必须完整保留解题所需信息，不能因为文本提取不完整而发布不可作答的题。
- 同一道题不能通过改标题、替换数字或拆分小问重复计数。改写题不得继续标成未改动的历年真题。
- 无法核实年份、题号或来源的题，不得伪造真题身份；可排除或在独立核对后明确归类为原创/改编题。
- 题库清单要能核对实际300题、来源构成、科目覆盖及重复检查结果，不把目标数量当成已完成数量。

### 5.4 作答与自评

**单选240题**：每题只有一个正确选项；提交后本地按标准答案判定，展示解析，接入原有进度与错题机制。包含Ⅰ、Ⅱ、Ⅲ组合判断的四选一题仍属于单选，不据此改成多选。

**综合60题**：

- 展示完整题干和全部小问，允许按小问记录文字答案、计算过程和必要的伪代码/代码文本。
- 提供参考解答、关键推导与评分点；参考得分须与各小问分值对应。
- 用户对照答案自行记录掌握情况或自评分，不以AI评分作为练习前提。
- 自评结果与客观题对错分开统计，不能把“已掌握”直接等同为系统判定答案正确。
- 不因涉及算法分析或代码书写而新增在线编译、运行测试或OJ判题。

300题是练习题库规模，不是一张正式模拟卷。本期未要求计时考试、整卷组卷、排名或历年整卷复刻。

## 6. 三题库分离与历史兼容

- 算法库、资料库、408库具有明确、独立的来源身份；不能仅靠旧字段`category=hot100`区分，因为旧教材题和旧生成题也使用该值。
- 三库的题目ID、缓存、筛选、列表位置与题库版本不能相互覆盖；练习记录继续按真实账号隔离。
- 原始算法ID不变；新408题使用独立ID。旧教材`ds-*`、旧自动生成`g-*`保留原身份，不按标题相似或相同力扣链接默默合并记录。
- 保留用户已有进度、错题、随手记、草稿、未同步操作和历史报告，不以删除旧数据完成迁移。
- 当前教材精选200题的覆盖逻辑不能再把算法入口或408入口替换掉，也不能将该200题直接截成100题冒充本期资料练习。
- 既有错题和学习分析若引用旧题，仍需能追溯原题；固定算法题与综合题自评不得混入同一种客观正确率。

后端和新增验证脚本继续使用Python；前端保持HTML/CSS/JavaScript。复用现有存储、队列和身份体系，不新增Node后端、第二套数据库或付费生成循环。未经授权不自动合并main、强推或发布。不得上传真实密钥、私人资料或运行产物。

## 10. 可直接转交实施模型的任务摘要

> 请按本文重构练习模块。只在练习模块采用计算机学习定位。首页采用顶部左侧引导、右侧原始力扣算法Hot100入口，下方左右对称排列资料练习100题和408考研题库。右上复用现有完整原始算法100题，不依赖上传资料，不新增代码运行平台。左下本期只做入口和承接页，资料接入暂缓；后续方向是同科目资料合并100题、上传后自动触发，只有单选/多选/判断/填空。右下必须主动检索历年408资料并实际整理固定300题，240单选＋60综合应用，四科覆盖，真题为主、原创补充，逐题记录真实来源；综合题对照参考解答和评分点自评。保留已有练习记录，停止旧每文件自动200题流程，避免教材精选覆盖固定题库。按验收清单交付可用页面、真实题库、来源清单和验证结果，不把三个入口都做成占位页。
