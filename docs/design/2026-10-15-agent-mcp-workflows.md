# Agent 学习工作流与真实 MCP 接入

## 第一版范围

按现有课程助手的产品边界，实现资料问答、总结、开放练习、薄弱点分析和复习计划预览。保留既有非流式、流式问答与题库接口。默认工具只读取请求提供的课程片段和学习记录，不修改文件、不联网搜索、不自动保存计划。

## 方案选择

选择轻量的结构化工作流：识别任务 → 发现 MCP 工具 → 检索/读取原文或分析作答/构建计划 → 生成答案 → 验证来源 → 返回结果。相比引入大型图框架，它更适合目前的原生 Node 项目，步骤可测试，取消与失败处理也更直接。自由模型工具循环和额外联网服务留作后续可选扩展，不把它们伪装为已实现功能。

## MCP

采用官方 v2 Client/Server SDK，通过 stdio 启动独立的本地课程工具服务，完成真实的初始化、工具发现、调用和关闭。每次工作流创建独立连接并在 finally 关闭，避免跨请求共享用户资料。服务没有 AI 密钥，也不扫描本地文件；请求上下文由后端绑定到工具参数。

工具：`search_materials`、`read_source`、`analyze_progress`、`build_review_plan`。参数使用 Zod 验证，工具声明只读。网关继续提供命名、超时和取消，调用者无法用参数覆盖绑定的资料与记录。保留外部 MCP 适配器边界。

## Agent

独立工作流模块负责任务路由与执行，原有模型提供者只负责模型传输。课程型任务先检索真实材料，资料不足时明确结束；学习分析与计划可以只依赖作答记录。模型失败时返回明确标识的本地工具结果或原文摘录。

新增 `/api/agent` 与 `/api/agent/stream`，保留 `/api/ai`、`/api/ai/stream` 兼容行为。流返回可读的处理阶段和已验证完成事件，前端显示处理进度。新的来源 ID 必须来自本请求实际读取到的原文。计划只生成预览，不改浏览器现有计划。

## 数据与限制

浏览器仍保存资料与题库。上传文档不会因接入 MCP 被写入新数据库。新增上下文严格限制候选原文、题目元信息和最近作答数，避免把整个大文档或不必要的学习数据发送给模型。学习工具结果不包含凭据，模型历史仍只接受 user/assistant 文本。

## 验证

保留原有 39 项测试和浏览器回归；新增真实 SDK 的 stdio 握手、发现、调用、参数验证、请求隔离和进程关闭测试。覆盖各任务路由、无资料、工具故障、模型故障、取消、来源伪造和流式完成事件，并验证页面通过真实 MCP 链路完成课程问答与计划预览。
