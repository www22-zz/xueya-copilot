# 队友完整功能接入方案

## 来源和基线

来源是桌面 `xueya-copilot(1)/xueya-copilot`，用户已确认其中前后端功能都需要保留。以当前 `main` 的模块整理版本为基线，在独立集成分支接入。原始队友目录保持不动，不导入嵌套仓库、依赖目录或本地密钥。

## 保留内容与落点

| 队友新增能力 | 接入位置 |
| --- | --- |
| 液态玻璃界面、题库弹窗和记忆卡片页面 | 前端 HTML/CSS 与 `frontend/js/ui/views.js` |
| PDF、DOCX 文本提取与上传解析 | `backend/rag/parsers/`、RAG 服务、前端资料服务、解析 HTTP 适配 |
| 流式问答与生成状态 | 模型适配器、Agent 流程、SSE HTTP 适配、前端问答服务 |
| 资料知识点提取、按知识点 AI 出题与题库保存 | Agent 练习模块、前端练习服务、页面控制器 |
| 基于答错次数的复习提醒 | 共享学习规则与记忆页面 |
| 队友新增测试 | 保留为解析、模型接口和记忆规则回归 |

## 合并原则

采用按功能迁移，保留模块边界和全部可用功能。保留已有非流式 `/api/ai` 接口与直接文件预览回退，新增 `/api/ai/stream`、`/api/parse`、`/api/topics`、`/api/questions`。默认不连接 MCP，保留此前工具网关及分工指南。

来源响应流被截断或没有有效完成事件时，前端回退到本地摘录，不把半段 JSON 当作完整答案保存。解析失败保持明确的待解析状态；扫描 PDF 没有 OCR，不能声称全部文档均可读取。

## 验证

原有 21 项测试作为基线。新增并保留队友的 PDF/DOCX、流式代理、出题、知识点与记忆规则测试，另外验证 UTF-8 分段、流中断和资源路径。浏览器覆盖原有学习流程，以及新文档解析、流式显示、AI 题库、记忆卡片、存储恢复和手机布局。
