## 队友怎么对AI说

在项目根目录打开AI编程工具，把下面这段发过去，将A替换为所领取的大任务和真实路径即可：

```text
请执行 docs/tasks/大任务/A-前端与完整学习空间.md 的完整大任务。
先阅读项目与该文件里的完整指令，自行安排内部小步骤，直接实现、测试、修复和联调。
已有实现先核验复用；不要只写计划、只做第一步或因为任务多而缩减范围。
在该任务指定的大任务分支上分阶段提交；维护指定交付进度文件，每阶段完成后继续下一阶段。
上下文不足时先保存检查点，下一轮读取进度继续；需要其他模块时按统一接口使用可替换Mock推进独立部分，再完成真实接通。
只在缺少必要的产品决定、凭据或资料时具体提问，不让我每完成一个小步骤再派一次任务。
最终按任务单交付可运行成果、真实验证、分支/PR、已知限制和接口交接，不自行合并main。
```

后续换了AI对话，只需说：

```text
继续上次的大任务。先读取原任务单和它指定的docs/delivery/进度文件，检查当前分支/改动，从尚未完成的下一步继续实现与验证，不重新做已完成部分。
```

这是持续开发安排；一次对话有上下文或运行限制时靠进度文件续接，并不表示AI一次消息能无限运行。

## 大任务之间怎样配合

1. **E先在自己的任务里尽早完成接口/schema/Mock和默认存储决定**，供所有模块共用；不用负责人额外派“任务00”。A～D可同时盘点现状、做独立逻辑和交互，通过可替换适配器继续开发。
2. **A、B、C、D各自交付整个模块。**资料属于B，问答与学习业务属于C，MCP包装属于D，页面属于A；底座和公共接线属于E。不能四方各自造一套资料库或学习算法。
3. **F现在开始建黄金集、跑基线、写报告正文和收集证据**；之后跟着真实功能持续评测，不在最后临时补报告。
4. **分阶段集成和验收**：先资料→问答→原文核对，再笔记→测验→诊断→复习，继续图谱、多模态、Agent工具与恢复。这是AI内部实现顺序，不是你要再次派发的小任务。

模块内的专项测试由作者完成；F做独立和交叉流程验收。E组织公共接线；是否合入main由负责人审查决定，AI不自动覆盖或强推。
