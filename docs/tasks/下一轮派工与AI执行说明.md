## 2. 启动顺序与交接

1. 所有队友先拿最新 main，阅读本文件和自己范围，核查已有代码与测试。
2. G1 先发布公共接线约定：能力状态、任务状态、模型用途、错误/取消、确认保存和新增路由；不是等 G1 全包结束才开始其他工作。
3. G2/G3/G4 可同时推进各自模块。先给出数据样例/适配端口，再逐步真实联调；Mock 只用于独立开发，不写成最终交付。
4. G5 先复用现有媒体能力，核对服务配置；长任务和音频流程接同一队列/账本。真实 API 测试需要明确预算。
5. F 现在开始基线、资料、报告和自动检查。每个包提交 PR 后，F 对照其任务验收，负责人决定合并；其他队友正常合入更新后的 main，不重置已有工作。

```text
请执行学涯 G1「学习体验与公共接线」完整大任务。我授权你在这个工作包范围内实现、测试、修复和联调。

前端保留 HTML/CSS/JS，后端、测试、CLI 和新验证脚本使用 Python。所有 AI 仅调用外部 API，不安装本地模型/GPU 运行时，不新增 Node 后端，不另建数据库、任务队列或调用账本。

最终交付可操作的页面和业务、兼容说明、实际测试、已知限制、提交并推送任务分支、创建 PR。不自行合并 main、强推、删除私人数据或联系其他队友。
```

领取其他包时，分支名和进度文件一并按第一张表替换。不要只替换 G 编号却仍提交到 G1 分支。
