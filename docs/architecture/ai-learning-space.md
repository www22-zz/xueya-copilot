## 2. 产品定位与一级结构

面向计算机专业学生的 AI 辅助学习空间，第一版优先完善计算机基础课程与考试复习主线，保留 Hot100 和已有进阶课程作为拓展。

### 2.1 结构

```text
AI 助手（默认首页）
├─ 对话、课程主题答疑、题目辅导
├─ 今日任务、继续学习快捷入口
├─ 对话内 AI 小测
├─ 对话内请求学习规划
├─ 按需生成知识框架
├─ 知识框架历史（二级入口）
└─ 个人参考资料管理（二级入口）

学习中心
├─ 课程学习
│  └─ 内部按学科、课程、章节、专题组织
├─ 练习
│  └─ 固定题库 / AI 生成练习；内部按题库、学科、专题筛选
├─ 复习
│  ├─ 错题重练与原有随手记
│  └─ 已采用计划中的到期、逾期复习任务
└─ 学习分析
   ├─ 分析报告
   └─ 我的计划：当前执行 / 草稿 / 历史

账号、设置、用量等辅助入口：沿用既有体系
```

- 学习中心左侧从上到下必须为：**课程学习、练习、复习、学习分析**。
- 学科和专题是上述大模块内部的分组、筛选和关联信息，不是新的一级模块，也不另建一个强制先进入的“专题中心”。
- 思维导图在产品中称为“知识框架”或“知识框架导图”，属于辅助学习能力，有完整编辑视图和二级历史入口，不增加一级导航。
- “学科/知识点”“视频课程”“旧平台 courseId”是不同概念。保留旧作用域约束，通过显式映射关联，不能简单改名或将前端选中的学科冒充服务端数据权限。
- 首页以 AI 聊天为重心，保留现有会话能力。今日任务可直接打开任务内容，继续学习可恢复实际保存的课程、题目或对话状态。
- 沿用现有配色、字体、深浅主题、动效和交互风格，集中调整导航及功能布局。新增页面使用一致样式，保留移动端适配与可访问性。

## 3. RAG 与问答边界

### 3.1 资料范围与用途

- 平台预置资料共享，作为服务端维护的受保护知识参考。
- 用户上传资料仅供本人账号检索。当前用户问答可同时参考平台预置资料和本人补充资料，不能检索其他账号资料。
- 新 RAG 端口仅供问答解释取证。课程目录、出题、评分、学习分析、规划、知识框架生成不直接检索此库。
- 知识框架可以整理已经生成的回答；对某个节点发起解释属于一次新的问答，可经正常问答链路使用 RAG。不得通过先自动提问再出题等方式变相实施“根据资料自动出题”。
- 用户上传入口放在 AI 助手的附件/个人参考资料二级管理中，显示本人文件名称、处理状态及管理操作。上传未索引完成时不得显示“已可检索”。删除/停用后退出未来检索，历史回答保留当时的公开来源快照。
- 本人资料的管理复用既有能力；平台内部正文的保护不能因为本人拥有文件上传能力而放宽。

### 3.2 回答方式

1. 根据问题检索允许范围的资料，由 LLM 理解、组织、解释并以自己的话回答；术语、公式和必要代码保持准确，避免大段逐字搬运。
2. 检索成功但没有有效依据时，以通用知识回答，清楚标记依据范围；不可编造资料出处。
3. 检索异常与“没有命中”是不同状态。异常可按问答策略降级到通用知识，但必须如实提示参考服务暂不可用；不能伪报“已检索且没有资料”。
4. 有资料参考同时补充通用知识时，区分来源支持的内容与补充解释。资料冲突或不足时保留不确定性。
5. 依赖 LLM 的回答在没有可用模型、调用失败或结果不完整时显示未完成。不能将检索原文直接包装成成功答案，也不能把半段流式输出存成正式完成结果。保留现有有依据、明确标注的确定性队列计算兼容路径；它不属于本地 AI 推理，也不能伪装为已完成的模型回答。
6. 允许显示简要来源名称、真实章节/页码等元信息；不存在的位置不能推测。来源名称面向用户，不暴露内部路径、供应商密钥或后台实现。

### 3.3 黑盒保护与旧契约的兼容

“黑盒”是产品 HTTP/API 与 UI 对普通使用者的访问控制，不承诺对拥有服务端磁盘访问权的人提供源码或资料保密。

- **平台资料正文不得发送到新界面，也不得通过其他读取、下载、搜索、预览、导出接口绕过权限取得。** 不能只移除“查看原文”按钮。
- 检查 bootstrap/workspace、source/sourceDetails/sourceObjects、SSE、历史消息、缓存、静态资源及导出中是否夹带受保护 `quote`、chunks 或全文。公开示例须明确标记，不能把受保护库打包进前端 JS。
- 服务端内部可保留原文、版本、引用和审核证据；公开 DTO 只投影允许展示的元信息。已完成回答和报告不应因后续资料更新而伪装使用新版本。
- `docs/api-contracts.md` 中旧 Source 包含 `quote`，这与新平台库公开策略存在边界差异。**不得直接删掉旧契约字段，或将全部旧调用偷偷改成另一种结构。** 新界面使用新增/扩展的公开来源投影；旧接口继续支持其合法旧用途与可访问来源，但对受保护平台正文执行服务端权限限制。
- 既有 `/api/ai*`、`/api/agent*`、`/api/learning/*`、`/api/platform/rag/*`、`/api/platform/knowledge/*`、资料读取与通用实体/作业结果接口，不能成为新受保护库的旁路。若联调需要改变共享契约，由实现 Agent 明确变更范围和兼容测试，不修改队友检索算法。

### 3.4 与 RAG 队友的对接合同

以下是语义合同，不要求其内部函数采用相同命名：

| 项目 | 要求 |
| --- | --- |

| 检索状态 | 现有 `rag-1` 使用 evidence_found / insufficient / conflict，并独立返回 warnings 与 supportChecked=false；新产品可在适配层归一化，但不改旧结果结构，不能将降级警告直接等同于无命中 |

| 用途 | 仅问答端可调用；其他学习工具用课程/题库元数据与实际用户记录 |

### 3.6 入库、检索及证据链必须保留的机制

**入库与修订：**

- 支持 TXT/Markdown/PDF/DOCX/PPTX；自编 Markdown 可直接解析，不需要 OCR。`materials/stack-queue/栈与队列知识库.md` 是共享内容文件，不是已经导入当前数据库的证明。
- 新 UI 的 `review=1` 进入校正/确认生命周期，`knowledgeReview.confirmedRevision` 必须与 `contentRevision` 一致。未确认的当前修订不能出现在 sources/read/index/Agent 选择中；编辑、OCR 或重新解析后需重新确认。
- 现有 `reviewed(doc)` 对没有 knowledgeReview 的历史/自编 Markdown 保持兼容；不要批量补入待确认标记让已有可用库突然消失，也不要将编译/规则验证自动改称人工全文审校。迁移门禁应显式设计，并保留原状态和内容修订。
- 原始解析、修订和来源定位保留；重发布时退出旧 source，并使旧向量身份失效。不能为新 UI 直接写 chunks 绕过 `_publish`、read/validate、reviewed 和版本检查。
- Markdown 来源依章节定位，页码可为 null；不能把分段序号或标题序号伪造成 PDF 页码。代码、公式、表格保持完整块，不因前端展示截断而改变服务端依据。
- MinerU 对显式选择的一批原页逐页提交，保留任务 ID、缓存和原始响应，未知提交不自动重提；已知任务恢复只查询原任务。OCR、重索引是独立、可能付费的运维操作，不能因用户打开页面或“修复资料”而自动运行。
- Qwen 当前接入的是文本向量，不代表已经完成图片向量或完整多模态 RAG。身份包含 provider/model/revision/adapter/dimension，变化时旧索引不能冒充新索引。

**检索合同：**

- `RagService.search(scope, query, history=..., document_ids=..., section=..., mode=..., budget=..., limit=...)` 是复用端口；scope 必须由可信服务端适配层构造。
- 当前默认 hybrid、budget=2000、limit=6；budget 单位为 UTF-8 字节，不是精确 Token 数。不能为新页面无上限放大证据包，也不能把浏览器预览当完整来源。
- `lexical` 使用本地词法规则；向量检索在当前模型身份已有有效索引时调用外部 query embedding；向量缓存保存在同一 SQLite entities 中，余弦检索在本地 CPU 完成，不是本地模型推理。RRF 融合和可选 rerank 不另建向量服务。
- EMBEDDING_UNAVAILABLE、VECTOR_INDEX_UNAVAILABLE、VECTOR_API_UNAVAILABLE 等警告可能伴随仍有效的词法命中。保留 sources 和降级说明；不能一见警告就丢弃有效资料、伪报纯通用回答。
- `status=conflict` 保留冲突状态，`supportChecked=false` 仅表示检索未完成语义支持审核，不是回答已经正确。原文/位置校验与结论语义审核是两个步骤。
- 每次外部 await 后重新读取有效来源，避免删除/修订期间“复活”旧证据。read/validate 检查来源 ID、documentRevision、fileHash/textHash、页/块、偏移、原文及 version，不能为跨账号聚合删除这些检查。

**回答合同：**

- 保留“组织完整中文正文 → 论断与正文一批核验 → 发布最终正文”的现有流程。`claims` 是后台证据笔记，不能重新拼成页面上的原文清单，也不能用仅修改系统提示词来取代审核链。
- 短 `citeN`、quoteId 与 quoteSpans 仅对本次可信证据包有效；不得跨请求缓存别名或让客户端提供原文来获得审核通过。
- 引用重排应保护 Markdown 代码块、C++ 数组下标与内联引用；不要在新 UI 中用全局正则删除所有方括号内容。
- `answerStatus`、`verification`、`engine`、`workflow`、`toolCalls` 等真实语义保留。`done` / `ok=true` 本身不足以证明回答完整，须结合 answerStatus/partial 判断。
- 现有只读 Agent 的 planRevision/工具步骤，以及客户端“AI 学习规划”旧标签，不是第 8 节的可执行 StudyPlan。新规划工具应按用途提前路由，不能把旧只读工具步骤当成用户已采用的日程。

### 3.7 一次通用兜底：保留已验证能力，限制适用范围

- 开关为 `AI_RAG_GENERAL_FALLBACK`，`Config` 默认关闭；用户提供的当前配置明确为 1。文档不能通过读取/打印真实 `.env` 来展示密钥或宣称 API 已在线验收。
- 对资料不足、生成/核验失败以及实现中列出的可兜底原因，现有 `with_general_fallback`/`stream_general_fallback` 最多发起一次不同的通用回答请求。普通问答保留该行为，不叠加第二层前端重试。
- 新请求不带当前材料包，保留正常问题和有界对话上下文；“不带材料”不代表此前对话文本必然没有知识内容。清空 sources/sourceDetails/sourceObjects/claims，标记未使用知识库证据，保留 fallback.reason/attempts/sameRequestReplayed=false。
- 通过 `workflow.resetAnswer=true` 清除先前部分资料答案，避免与通用答案拼接。失败或中断可以保留已收到正文，但必须带 answerStatus=unavailable/partial 等状态，不能存成成功资料回答。
- 独立请求当前上限90秒、使用独立连接，但仍共用原运行预算、并发资源和账本，不额外赠送模型次数或成本预算。保留原失败/unknown 调用记录，不能将它改成成功或认为没有扣费。
- 权限拒绝、资料失效、预算耗尽、用户取消、等待用户/确认等，不通过通用兜底绕过；两次都失败就停止。
- 这与“重放同一个未知付费请求”不同。本规格继续禁止后者；不删除现有一次独立问答兜底，也不把它推广到评分、复核、规划、自动分析、OCR/索引的循环自动调用。
- 旧非流式/兼容入口及学习领域 workflow 不一定都走同一 wrapper。新 AI 首页必须接上实际已安装的问答链路，验证 HTTP 与 SSE 行为，不复制一条弱化的“先检索再直接问模型”旁路。

### 3.8 当前实现与新产品之间的待补边界

这些是新产品要求的适配工作，不应描述为队友检索算法未实现：

| 当前事实 | 新实现要求 |
| --- | --- |
| `Platform.user_id` 默认 local-user；资料 HTTP 和 Agent 多处通过 `p.scope(courseId)` 读取 | 实现可信账号与资料所有权策略：公共预置 + 当前账号私人补充。现有 course 过滤不等于不同登录账号的私人库隔离，不能仅修改前端 accountId |
| RagService 本身接受 Repository Scope，但现有宿主通常传共享作用域 | 通过策略/适配层分别在原所有者作用域读取公共及私人证据，再组合给同一问答；保持原始作用域映射用于 read/validate。不要全局改共享 p.user_id、重写历史数据归属或放宽 COURSE_MISMATCH |
| 现有服务返回原文 sourceDetails/sourceObjects/claims、工具结果和读取/导出正文 | 构建内部证据与公开来源两种 DTO，投影覆盖每个流事件、toolCalls.data/preview、run/checkpoint/result/history 和旧读取路径，不仅处理最终 sources |
| `chat-service.js` 旧 normalize 要求来源有 quote，引用点击默认打开原文 | 新界面增加只含公开元信息的来源解析与来源信息视图；仍能展示引用数量/定位。保留合法旧来源兼容，不能因没有 quote 就丢光来源，也不能点击平台来源打开内部正文 |
| 新上传支持待确认，旧调用/直接上传仍可不经过 review；旧自动出题 hook 仍存在但受 legacy 开关控制 | 私人补充和预置资料保持原复核/版本语义；新产品上传显式不触发资料出题，不仅依赖“当前开关恰好关闭” |
| legacy `mode=quiz`、practice/topics/questions、学习包/旧图谱服务仍可基于资料运行 | 保留旧兼容实现和历史对象；新小测/规划/分析/知识框架注册独立用途，不拿共享 RAG 原文作输入，也不能把所有旧工具直接开放给新 Agent |
| 私人数据库、已确认修订与真实向量缓存不在 Git 中 | 先检查已有导入及索引身份；缺失时报告准备状态和安全初始化选项，不自动重导入、替换、归档私人资料或付费重建索引 |

聚合实现须至少满足：内部来源键包含 owner scope + 原 sourceId，公共展示 ID 与原始定位映射仅由服务端管理；公共/私人文档的 read/validate 分别回到原 Scope；不能通过改写 fileHash、version 或 courseId 伪造归属。新 StudyPlan/知识框架的跨学科关联也不能破坏旧单课程验证。

分作用域检索后，最终证据包仍受同一次请求的全局字节预算、来源数量和模型/成本预算约束；不能因公共库和私人库各搜一次就将允许输入翻倍或创建额外预算。保留来源冲突与降级信息，最终发布前逐来源复核有效性。

旧 local-user 下的所有资料不能一律划为平台公共库。平台资料应有明确的受维护清单、来源/哈希及可核对的归属；仅凭文件名或存在于本机不能证明可共享。无法证明归属的旧资料保留在原兼容空间，按显式迁移规则处理，不能在新增账号后自动公开。

接口投影和权限限制在宿主入口、资源策略或新适配层落实。若确实需要修改共享 RAG 合同，先记录具体源码位置、受影响旧调用、兼容方案与验收用例，再与用户沟通；不要顺手替换检索、合并其他分支或联系队友。

### 5.3 客观题与主观题

| 类型 | 规则 |
| --- | --- |
| 客观题 | 由程序按版本化答案确定性判定，复用既有规则；不每次调用 LLM 判正误 |
| 有明确评分标准的主观题 | LLM 逐评分点给参考分、覆盖/遗漏/错误、依据和改进建议；分值范围由程序校验 |
| 无明确标准的主观题 | LLM 给内容分析和改进建议，不生成任意总分 |
| 算法代码 | 保留现有题解、力扣跳转；可做 LLM 文本分析，不因本任务增加不受控的本地代码执行或新的在线判题系统 |

- AI 生成客观题依其生成答案程序判定，明确答案来自 AI 题快照，不能等同正式题库人工审校质量。

- 评阅 queued/running/failed/cancelled/unknown 与评阅完成不同。失败保留答案，不记为零分或错误，也不自动触发重复付费评阅。

### 5.4 复核、人工修正与争议

- 支持用户说明理由后发起 AI 复核，也支持人工修正分数、结论或标记争议。
- 原答案、原评阅、复核和修正作为不可静默覆盖的版本/事件保留。最新有效结果由明确的规则派生，用户修正标为人工来源，不能伪装成 AI 同意。
- 后续统计使用最新有效结果；历史报告仍使用当时快照，显示后续已有修正即可，不回写旧结论。
- 主观题错题归类可参考明确的评阅结论；不确定、失败、争议结果不能强行判错。保留用户加入/移出错题、既有订正及笔记能力。

- 默认纳入学习相关对话，支持按时间、学科、专题调整范围、排除会话，并在报告中注明所用依据。
- 自动建议的会话分类允许用户修正；不将日常闲聊全部当成学习记录。纳入会话列表和排除设置必须可检查。
- 对话内题卡产生的作答按作答事件统计，不因同一文本同时存在于聊天而重复计数。排除会话只影响其对话分析，不自动删除已单独保存的练习记录，界面说明范围区别。
- 没有作答也可以分析已有课程、对话与计划活动，不能沿用旧“无练习记录一律禁止”的门槛；结论应限定证据范围。完全没有可分析活动时跳过调用并提示开始学习。
- 文本量按源提取有界摘录、增量摘要或分批汇总，保留原记录 ID 和覆盖/省略说明。不能把全部历史无上限提交，不能用无出处摘要冒充完整原始证据。

### 7.2 输出要求

报告至少包含：分析范围与时间、事实统计、学习主题/进展、待巩固或待检验知识点、计划执行与复习情况、具体下一步建议、依据与限制。

- 数量、正确率、分值和计划进度由程序计算；LLM 负责有依据的综合解释、可能原因和建议。
- 建议尽量定位真实课程章节、题目、知识框架节点或计划任务；查不到的内容显示为自主学习建议，不虚构内部资源 ID。
- 不以对话次数、观看时长、单次得分生成看似精确的全学科能力分、排名或学习收益保证。
- 可查看历史并继续追问，追问使用该报告的截止快照。需要新记录时显式生成新报告，不声称旧报告已经重新读取新数据。
- 根据分析生成规划，复用第 8 节的规划服务；报告建议不自动改变执行计划。

### 7.3 定期分析与本机补报

- 首版支持自动分析与手动生成。默认每周自动一次；用户可修改周期或关闭。基础统计随记录更新，不依赖 LLM。
- 调度运行在本机 Python 服务生命周期内，关闭浏览器不影响已运行服务；服务停止或电脑关机时不运行，不增加云端常驻后端。
- 配置、下次到期、上次已处理窗口、上次成功快照水位、作业 ID 及结果状态持久化。
- 服务启动后发现错过周期，且有新的可分析记录时，将错过范围合并补一份；不能逐日/逐周补跑多个模型调用。补报标明覆盖范围和实际生成时间，不能漏掉其声称包含的中间记录。
- 没有新记录就跳过并推进调度窗口，避免每次轮询重新检查同一到期项。未分析的新记录须保留到后续有效窗口，不能只因推进日期而丢失。
- 新记录检测应包括新的用户作答、评阅纠正、课程完成、有效对话和任务事件；报告生成、报告追问、系统自动摘要等派生输出不能不断触发下一份报告。
- 多个调度器/worker、重复启动和手动/自动同时提交时，按账号、窗口与快照水位幂等提交；同一批输入不能重复付费生成相同报告。
- 每个付费作业默认单次尝试。failed/unknown 不能因“还没报告”就被下一次轮询或重启自动付费重放；未知结果按现有账本流程核对。可提示用户处理，保留后续新数据。
- 后台任务以持久账号身份运行，不依赖浏览器标签页、当前选中学科或活跃 Cookie；只处理已启用该功能的账号。模型未配置、预算不足时显示真实原因，保留待分析水位，不生成假报告。
- 有新报告时提供站内提示/最新报告入口，恢复页面能查到；不自行接入邮件、短信或站外通知。

## 8. 可执行学习规划

### 8.1 输入与触发

必须明确：**学习目标、时间范围、可用时间**。支持具体截止日期、持续时长、每日/每周预算、每日覆盖值和休息日；当前基础与学习记录作为辅助。

- Agent 识别用户实际规划意图，如“帮我规划”“安排两周复习”，调用统一工具。不能仅靠出现关键词，或因“解释学习规划是什么”而创建计划。
- 已在对话中明确的信息直接复用；缺失、矛盾或已过期的信息一次简洁追问。保存提取值、来源与用户修改，不将模型猜测作为已确认事实。
- 保留“按默认条件安排”的快捷选项，用户主动选择后展示所采用假设。
- 学习分析内使用相同字段与校验，可从报告带入目标建议和真实进展，仍需补足时间条件。

### 8.2 规划方法

采用 **LLM 理解目标/拆解知识与任务 + Python 约束校验/资源匹配/排程**：

1. LLM 输出结构化学习阶段、知识点与任务候选，说明目标和理由。
2. 从平台与本人课程、固定题库及本人练习记录匹配真实资源。不得把 RAG 原文变成规划输入，或要求所有目标先上传资料。
3. 站内资源不足时，允许 LLM 配合现有 Search/MCP 搜索找到真实外部资源，保存标题、链接及来源；不能把搜索摘要冒充已经完成观看或内容审核。
4. 没有可用搜索结果时，仍可安排明确的自主学习任务，给出目标与完成要求；不能伪造 URL 或站内课程。用户可补链接。
5. 按阶段组织，具体排到每天。程序验证日期、每日总预算、休息日、先修/顺序和资源权限。一个综合计划中的所有学科共享每天预算。
6. 时间不够时展示无法安排的任务/工作量及取舍建议，允许用户修改期限、预算或范围；不能压成不合理时长或伪称全部可完成。

现有 `backend/agent/planning.py` 可复用时间预算、依赖和重排的部分逻辑，但当前输入依赖资料概念图；须以课程/题库的知识目录、任务与真实记录适配新方案，不能直接套用旧资料学习包。

### 8.3 状态与采用

```text
需求待补齐 → 生成作业 → 已保存草稿 → 用户明确采用 → 当前执行计划 → 历史计划
                         └─ 修改后仍为草稿
当前计划修改 → 变更草稿/差异预览 → 用户明确采用 → 新版本当前计划
```

- 每个账号同时只有一份当前执行计划，可包含多个学科；支持多份草稿和历史计划。
- 生成即保存草稿，不直接写入当前待办。模型输出、课程材料或网页中的指令不能冒充用户确认。
- 采用使用服务端草稿 ID、expectedRevision、confirmed 与 operationId，校验账号/版本后事务提交。重复采用返回同一回执，并发采用不能产生两份当前计划。
- 切换到另一份计划时明确当前计划变化，旧计划转历史，保留其完成、延期及未完成任务，不删除。
- 修改当前计划先展示差异，采用后生效。已完成任务不可被重生成或排序抹掉；稳定任务 ID 与任务实例用于关联历史。
- 第一版必须支持保存、资源跳转、手动完成和手动延期；修改每日可用时间、休息日或期限时走调整预览。
- 手动完成/延期是明确的任务操作，不要求用户再次点击“采用整份计划”；接口仍做 revision、幂等和预算检查。若变更需要移动其他任务或更改预算，先生成差异预览再采用。
- 延期不能静默占用休息日或超出预算/截止日期。发生冲突时提供选择其他日期、调整预算或重新规划的入口，保留原任务，不自动挤掉其他任务。
- 课程完成自动同步已匹配的普通课程任务；题目作答结果独立保存，首版任务完成仍可手动确认，不把生成题/提交失败视为完成。

### 8.4 管理位置与展示

- 统一管理位置：**学习中心 → 学习分析 → 我的计划**。
- 首页今日任务打开同一任务/资源；查看全部进入当前计划。
- 聊天规划：展示文字说明、任务安排摘要、知识框架卡片，保存草稿，提供查看详情、修改和采用。
- 分析入口规划：弹窗展示文字说明、任务安排和知识框架，支持预览、编辑、采用与取消。宽屏可分区，窄屏可切换视图，不强行压缩导图。
- 计划详情以阶段/每日任务清单执行，提供知识框架入口。
- 两个入口使用同一服务、同一 planId/revision，不各自生成一份独立日程。

## 9. 知识框架导图

### 9.1 语义与生成

**知识框架是概念、知识点及其关系的结构图，不是任务关系图或日程图。**

- 围绕本次学习目标生成：整门学科先展示总览，具体主题细化，支持继续展开和编辑。
- 规划自动附带对应知识框架；普通答疑按用户点击或对话指令生成，例如“整理成知识框架”“梳理这些概念的关系”。不每条回答自动附图。
- 生成依据可为目标、已生成讲解、用户选择的对话和课程/题库知识目录。来自通用知识的节点不能伪造教材或视频出处；不得直接检索受保护 RAG。
- 示例：操作系统 → 进程管理/内存管理/文件系统；进程管理 → 进程线程/调度/同步互斥/死锁。日期、每日时长、完成按钮保留在任务清单中。

### 9.2 编辑与关联

- 保存结构化节点/边，前端渲染，不以一张生成图片或不可编辑截图替代。
- 支持节点增删、文字编辑、折叠展开、缩放、拖拽布局/层级和合理的自动布局，支持撤销/重做及编辑持久化。
- 用户可选中节点提问、请求扩展或改进；“解释给我听”与“修改导图”区分。修改以稳定 ID 的局部 patch 为主，预览后应用，保留用户布局和已编辑内容。
- 允许关联课程、题目、讲解与学习计划知识点。点击相关内容精确跳转并能返回，不虚构已存在的资源。
- 拖动或编辑知识节点不自动改变任务日期、不完成任务、不覆写先修图谱或掌握状态。
- 采用计划不意味着用户手动改过的框架要被重新生成；需要更新覆盖范围时，提供独立差异/扩展操作。

### 9.3 保存与查找

- 与原对话或计划关联并自动保存已完成产物，编辑显示保存状态，失败保留本地待恢复内容，不伪报已同步。
- AI 助手内部提供“知识框架历史”二级入口，按学科/专题筛选，支持重命名、删除、打开原上下文。
- 存储 `frameworkId` 与 `planId/sessionId` 的关联；计划和知识框架是两个独立实体，不共用一份任务树结构。
- 数据按账号隔离。删除导图不删除源对话、作答或计划；原来源删除后保留可解释的失效关联，不错绑其他对象。
- 现有 `concept_service.py`/`concepts.py` 强调资料证据及先修关系，不能直接强制所有自由节点都有 RAG 引文；可复用明确适用的校验逻辑，不以放松旧图谱验证来承载自由编辑。

## 10. 典型跨模块流程

### 10.1 从聊天开始

提出问题 → 问答检索/通用知识讲解 → 主动请求知识框架或小测 → 聊天作答并保存 → 客观判定/主观评阅 → 在练习查看或复习 → 后续报告引用真实记录。

### 10.2 从课程开始

官方播放器学习 → 带课程/章节上下文答疑 → 匹配或按需生成小测 → 用户手动确认本节完成 → 同步当前普通课程任务 → 到期复习任务集中进入复习模块。

### 10.3 从分析到执行

手动/定期报告 → 查看依据与建议 → 请求规划并补齐必要信息 → 草稿、文字安排与知识框架 → 采用 → 首页今日任务 → 手动完成/延期 → 新事件进入下一份报告。

所有跳转传递稳定对象 ID 与可恢复位置；通过资源服务核验权限和版本。不能只跳首页让用户重新查找，也不能让导航状态成为账号权限依据。

## 11. 数据与事件设计要求

优先复用 entities/revisions、已有事件日志、文件与 JobQueue。下表是逻辑实体，不要求建立同名新表或新数据库。

| 实体 | 关键内容 |
| --- | --- |
| AccountScope | 服务端稳定账号 ID、来源权限、当前计划引用；展示用户名与数据所有权分离 |
| Subject / KnowledgePoint | 稳定 ID、显示名、父子/关联信息，用于模块内部组织与跨模块关联 |
| VideoCourse / Episode | platform/private、owner、官方来源平台 ID、原链接、分集、真实简介/时长、知识点、可用性 |
| CourseProgress | account、episode、手动完成、可用播放位置、来源事件、版本 |
| Conversation / Message | 稳定 ID、账号、时间、学科/专题、来源上下文、分析排除状态、工具产物引用 |
| Question / Quiz | 固定/历史/AI 来源、账号范围、题目版本、答案/评分点、知识点与审校状态 |
| Attempt / Evaluation / Correction | 原始答案快照、客观结果或评阅状态、评分点、模型、复核/修正链、最终有效来源 |
| StudyPlan / Task | planId、revision、状态、目标、期限、每日预算/休息日、阶段、稳定 taskId、实例、资源引用、完成/延期历史 |
| KnowledgeFramework | frameworkId、revision、节点/边/布局、生成范围、来源上下文与资源关联，独立于计划任务 |
| AnalysisReport | 截止快照、筛选/排除、事件水位、统计、分析结论、建议、引用、限制、模型及历史追问 |
| AnalysisSchedule | 账号、开关/周期/时区、到期时间、已处理窗口、上次成功水位、幂等作业与异常状态 |

### 11.1 事件与一致性

- 学习活动使用稳定 eventId/operationId，来源可为 chat/practice/course/review/plan；重复提交和刷新不能重复计数。
- ChatQuiz 引用同一个 Question/Attempt，课程与计划引用同一个完成事件，复习与计划引用同一个任务实例。
- 复核、人工订正更新“有效结果”投影，不篡改原答案、不增加答题次数；日统计按约定的原作答时间保留，修正本身可作为新的分析依据。
- 时间戳可用 UTC 存储，日期排程、周窗口、到期/逾期统一使用 Asia/Shanghai；未来时间、跨日和窗口边界必须测试。
- 所有变更使用现有事务、版本校验和幂等回执。慢模型请求不长时间占据数据库写锁或用户确认事务。

### 11.2 身份、缓存与迁移

- 后端从有效会话/既有授权上下文确认身份。不能仅因前端传了 accountId，就认为私人记录隔离已经成立。
- 审计旧 `local-user`、`practice:<account>`、course scope、浏览器 workspace、课程 localStorage 等真实映射。现有账号文档与代码可能存在历史差异，以实际校验为准。
- 登录切换时清除当前页面中的上一账号私人数据，取消/隔离迟到响应；缓存、IndexedDB/localStorage 与服务端资源都按账号归属隔离。
- 多学科综合计划通过服务端授权的跨学科聚合层实现，不能伪造单一 courseId 或移除现有 COURSE_MISMATCH 检查。
- 迁移保留原 ID、修订、题目与作答、笔记、错题、课程状态和报告。无法判断归属的旧本地数据留在原兼容空间或显式导入，不能复制给所有账号。
- 私人数据库不提交；使用隔离副本验证升级和恢复，不清空数据库“重建成功”。

## 12. 接口与工具边界

### 12.1 分层职责

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 浏览器 | 页面、表单、题卡、播放器嵌入、导图编辑、状态显示与精确跳转 | 权限裁定、客户端权威判分、伪造学习统计 |
| Agent/学习领域 | 意图识别、结构化生成、知识解释、评阅、基于快照分析 | 自报执行成功、跨账号查数据、直接更改库或随意执行网页指令 |
| 平台接入 | 身份/作用域、资源解析、作业、事务、版本、预算、幂等、调度 | 第二套独立存储或模型账本 |
| RAG 适配 | 复用现有 RagService/问答审核链，在其外完成可信私有范围与内部证据/公开来源投影 | 重写队友的检索实现，或用 RAG 出题、排程、生成分析及直接构建导图 |
| Search 适配 | 复用既有 MCP 搜索，为自主学习资源查找返回真实链接 | 未授权联系外部人员、抓取/执行任意网页指令 |
| 视频适配 | 官方播放器/接口与结构化课程元信息 | 自托管、镜像、非官方解析、虚构播放遥测 |

### 12.2 新能力的逻辑 HTTP 合同

下表是必须覆盖的能力合同，**不是对现有路由已存在的声明**。优先复用合适的旧路由；需要新路由时，可在同一主程序下采用 `/api/learning/center/...` 的子命名空间，核对现有 catch-all 路由的注册顺序。实施 Agent 须补充最终路径与请求响应合同。

| 能力 | 请求关键项 | 返回/约束 |
| --- | --- | --- |
| 公开问答/工具流 | question、sessionId、messageId、结构化上下文、取消信号 | 文字增量、工具状态与已完成产物引用、公开 sources；最终 done 才是完成 |
| 课程目录/本人课程写入 | 过滤条件；个人课程元信息、expectedRevision、operationId | 公开平台课程 + 本人私人课程，后端校验来源和归属 |
| 课程完成/续播 | episodeId、完成或已获取进度、版本、operationId | 课程状态及关联任务同步回执，观看进度来源可辨认 |

| 我的计划/今日任务/复习 | 状态、日期、分页/过滤 | 当前/草稿/历史，或账号内到期队列，引用同一任务 |

| 框架生成/扩展 | 明确范围、来源上下文 ID、选中节点、框架 revision、指令 | 结构化框架或局部 patch；不直接检索 RAG |

| 作业恢复/取消 | jobId、身份、operationId（需要时） | 沿用主平台真实状态，不重新创建一个付费请求 |

### 12.3 共同约束

- 保留现有同源、Host、会话、token 和错误语义；对象读取、列表、写入、导出与作业结果均校验账号。
- 异步生成使用现有持久作业，返回 jobId 后可刷新恢复。作业状态、产物完成与 UI 动画完成分开。
- SSE 可以兼容扩展或使用新工具事件适配层；不要把新版交互题卡/规划 JSON 直接混进旧 content 文本，让旧解析器损坏。
- 新产物建议以 artifactRef（kind/id/revision/status）引用；文字流与持久产物各自有明确完成信号。done 前断流、格式损坏、取消或迟到响应，不得产生重复题卡或覆盖新状态。
- 列表与只读恢复不调用 LLM；打开报告、框架、题目或计划历史不产生隐含重新生成。
- 复用 `sourceDetails/sourceObjects` 的旧客户端需要与公开元信息 DTO 同步适配；保留 `answerStatus/verification/fallback/resetAnswer/partial` 等状态，不能把新图卡工具输出接到旧 mode=quiz 或只读 planRevision 上。
- 使用已有请求/输出上限并按新能力有界扩展，显式处理输入裁剪；验证模型 JSON、真实资源 ID、评分范围和计划约束，不执行模型 HTML/JS。
- job/input、网页、笔记、题目、用户上传内容都作为数据，不能提升为系统指令、账号身份或写入确认。
- 付费结果未知时保留 unknown/待核对，幂等 key 只能防本站重复提交，不能宣称供应商绝不会重复扣费。

## 13. 建议实施顺序

每阶段可独立验证，但不能把中间阶段当成已完成整份首版要求。

1. **基线与映射**：从至少包含 `b651dd9` 的当前主线核对实际工作区、数据归属、现有路由与契约；先建立新版 RAG 回归基线与测试隔离，制定兼容升级和恢复方法。
2. **平台边界**：在既有 RagService/问答审核链外建立可靠账号解析、资源权限、公开来源投影和用途适配；先通过工具事件、历史及旧 API 的黑盒旁路用例，禁止用更换检索系统完成新产品权限。
3. **导航与资源目录**：重组 AI 首页和学习中心四项结构；个人/平台课程、知识点映射与官方播放器接入；移除上传自动出题触发。
4. **练习与评阅**：统一聊天题卡和练习服务；新增有界 AI 小测、主观评阅、复核/订正及来源标记；保留固定题和旧进度。
5. **计划执行**：结构化需求、Search 资源匹配、约束排程、草稿/采用/版本、任务与课程/复习同步；完成“我的计划”和首页今日任务。
6. **知识框架**：独立结构与编辑器，聊天按需/规划自动生成、局部编辑、历史筛选和关联跳转；不要使用任务清单充当知识图。
7. **综合分析与定时补报**：多源事件快照、依据/限制、报告追问、每周调度、设置、去重、补报与未知结果处理。
8. **内容与验收**：查找/核实正式视频，按覆盖补题；执行全量回归和端到端闭环，更新最终接口、用户指南与交付限制。

既有 RAG 服务和问答能力已接通，禁止将第 2 步演变成重写队友算法。新账号策略或公开投影合同尚未完成时，可用受控适配器验证上层功能，但必须列为未交付边界，不得用页面效果代替权限验收。
