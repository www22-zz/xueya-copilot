## 本次实现

- `backend/agent/planner.py`：通过现有外部模型端口输出严格JSON决策；初始计划、步骤ID和可核验完成条件由服务端检查。协议为 `xueya.readonly-agent.v1`。
- `tool_adapter.py`：从现有真实MCP会话发现可用工具，再按宿主白名单提供用途和输入schema。允许搜索、原文读取、进度分析、只读计划预览，以及平台可用的错题、FSRS队列和图谱查询。不暴露确认、写入或任意外部工具。
- `orchestrator.py`：每轮执行模型选择的一个动作，验证结果，再将有界观察交回模型。支持 `call_tool/revise_plan/ask_user/finish`。已完成步骤不能删除或改写，完成条件不能降低；重复调用不再执行。
- `result_evaluator.py`：根据实际工具结果检查完成条件；统计、计划、错题数量等由服务器整理，模型不能自报成绩、保存或掌握情况。课程答案继续使用P0逐条论断核验，不接受合法引用ID包装的无依据结论。
- `backend/xueya/learning_integration.py`：复用ScopedModel、官方SDK会话、课程身份、P0预算与来源快照。最终done在SDK会话退出后发布，兼容非流式与流式HTTP，不在人类等待阶段持有工具连接。
- 现有run/checkpoint/result附带计划历史、实际动作与观察用于审计。前端通过原工作流进度区显示计划与查询步骤，保留可选agent元数据，无新增导航或页面。

## 使用方式

正常使用原聊天入口，发送例如：

- “帮我学习队列这一章，先找资料再核对原文。”
- “分析队列错题并准备巩固资料。”
- “两周后考试，每天40分钟，安排队列复习计划。”

有模型配置且问题属于课程学习时，默认启用动态流程；普通问候、通用问答、图片聊天、原 `/api/ai`、章节/题库服务及无模型规则流程保留。服务端 `AI_AGENT_PLANNING_ENABLED=0` 可恢复原固定编排。请求体无法提高权限或限额。

`build_review_plan` 增量接受可选examDate/minutes，均有schema/日期校验，只生成预览，不改课程设置或保存计划；省略仍使用现有设置。预览仍采用已有学习规则，P1不宣称完成高级跨章优化。

## 预算与停止

见 `.env.example`：默认8轮决策、最多2次重规划、连续2次无新信息停止，每轮最多1536输出token（不超过P0每次上限）。所有决策和工具中的实际API调用共同受P0模型/工具/累计输出/时间/可选费用预算约束。

计划格式无效、模型请求结果未知不自动收费重试；不通过额外生成请求粉饰失败。完成条件不足会反馈给模型补充步骤，连续无进展则询问用户。来源修订/删除会阻止发布旧结果；取消会传播到模型和MCP并释放许可。

## 协议与实际边界

保留 `/api/agent`、`/api/agent/stream` 的请求字段、JSON基础字段和原SSE事件类型。增量 `agent` 包含status、plan/planHistory/planRevision、completedStepIds、observations、decisions、decisionCount、replans、stopReason。status为completed/partial/awaiting_user；request级完成不代表用户已经掌握知识。

P1只能完成只读查询、准备、分析和计划预览，不代替用户作答、FSRS自评、候选审核或保存。需要补充信息时，用户继续发普通消息；后续请求重新规划并利用原对话历史，**不声称恢复同一个持久化运行**。P2的单步队列推进、跨请求恢复及持久化总预算未实施。

对话历史与材料均视为不可信数据；模型输出schema、权限与证据校验是确定性边界，不把提示词当成授权。受控测试证明执行与分支流程，不证明真实模型的教学质量、规划成功率或学习收益。
