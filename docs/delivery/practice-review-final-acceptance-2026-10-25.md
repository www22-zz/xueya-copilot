# 练习 / 复习完整需求与 11 项问题修复验收

日期：2026-10-25。以对话中逐项确认的最终范围为准：本机 Python 服务 + SQLite，不增加云端依赖，不增加 AI 出题、代码编辑器、在线判题或独立笔记管理页面。

## 最终路由和状态结构

一级导航仅保留学习概览、问答、课程资料、练习、复习。

| 路由 | 页面 |
|---|---|
| `#space/overview` | 学习概览 |
| `#space/ask` | 问答 |
| `#space/knowledge` | 课程资料；原文与版本管理仍属于资料能力 |
| `#space/practice/hot100` | 官方 Hot 100 |
| `#space/practice/foundation` | 五科基础题 |
| `#space/practice/interview` | 五科面试题 |
| `#space/review` | 错题本及题目关联随手记 |

旧笔记、章节学习、复习计划、知识图谱入口直接删除，不保留重定向。

服务端按账号维护事件日志，课程固定为 `practice-global`；课程资料和问答继续使用原平台。浏览器按账号维护操作队列和草稿，分类分别保存筛选与浏览位置：

```js
{
  accountId, serverSeq,
  statuses: {
    [questionId]: {
      status: 'pending' | 'mastered' | 'wrong',
      confidence: 'unknown' | 'fuzzy' | 'mastered',
      wrongCount, correctCount, wrongEnteredAt, lastWrongAt,
      lastResult, masteredAt, lastOperationAt, revision,
      correctedAttemptIds // 已纠正的作答，防止同一次错误被重复撤销
    }
  },
  notes: { [questionId]: {text, revision, updatedAt, conflicts: []} },
  drafts: { [questionId]: {text, savedAt} },
  filters: {hot100: {}, basic: {}, interview: {}},
  ui: {category, positions: {}, language, mode, wrongSort, reviewFilters},
  rejectedOps: [] // 永久拒绝的操作回执，保留详情，不阻塞其他保存
}
// 单独持久化的离线队列：
[{opId, kind, questionId, payload, clientTs, deviceTag, state: 'pending'}]
```

正常数据写入 LocalStorage 和本机数据库。LocalStorage 写入失败时，按账号写入 IndexedDB 持久恢复日志，同时使用 SessionStorage 承接即时恢复；页面初始化先读取恢复日志，再获取服务端状态。已实际验证刷新、关闭标签页后重新打开均能恢复草稿，恢复连接后确实进入 SQLite。正常离线草稿按账号保留，重新登录原账号后恢复。没有云端服务器时，不承诺不同电脑之间自动同步；这里的同步指浏览器和当前本机服务，以及访问同一服务的会话。

## 11 项问题逐条验收

| 编号 | 修复与验收证据 | 结果 |
|---|---|---|
| F01 官方完整 Hot 100 | 依据官方题单建立独立清单，100 个官方题号、100 个唯一原题链接、17 个专题；补齐 19 题，移除非官方项和重复项，修正难度。保留仍在官方题单中的既有题目 ID，避免其进度和随手记错挂。 | 通过 |
| F02 手机随机入口 | 手机点击随机一题进入全屏详情；随机回顾共用相同选题入口。返回恢复列表，随机模式不会被改为顺序模式。Chrome 手机视口实测并截图。 | 通过 |
| F03 纠错对应具体作答 | `attemptId` 指向原作答，校验账号、题目、填空类型和错误结果；同一作答不会重复减数。两份独立浏览器会话各答错一次、各点击纠错后，服务端为 0 错 / 2 对，状态待刷。既有更早错误不会一起清零。 | 通过 |
| F04 拒绝操作卡住同步 | 接受、重复、拒绝逐项处理，已接受笔记从队列移除；拒绝记录留回执。无效纠错与有效笔记同批提交后，笔记确实进入服务端，重试不再卡住。未知 / 已移除题目也不再否决整个批次。 | 通过 |
| F05 搜索聚焦时列表不更新 | 远端掌握更新到达后立即重绘，不因输入框焦点而跳过；保留搜索词、焦点、输入选区以及当前编辑草稿。实测搜索聚焦下待刷列表从 1 行变为 0 行，详情不再保留旧状态。 | 通过 |
| F06 完成提示不复原 | 同步后重新协调完成标记、筛选结果与选中题；远端移回待刷后自动显示可练题，不再停留在“已刷完”。自身答错停留看解析的行为同时保留。 | 通过 |
| F07 错题最近排序 | 取最近答错和最近进入错题本两个时间的较新者。实测旧题移回待刷后重新加入，排在此前更晚答错的另一题之前；错误次数排序仍可切换。 | 通过 |
| F08 分组和固定顺序 | Hot 100 按官方 17 专题分段，专题内简单→中等→困难；基础 / 面试按科目、知识点、难度分段。随机权重不参与列表排序。验证分组不交错、组内难度有序，浏览器显示 17 个算法专题。 | 通过 |
| F09 独立笔记残留入口 | 设置 / 本地数据中的旧笔记标题、内容、预览、确认控件及处理器全部移除。平台契约仍保留，产品界面只提供题目随手记。浏览器确认旧控件不存在。 | 通过 |
| F10 旧数据残留 | 浏览器旧 v1/v2、工作区、待迁移及历史恢复副本清理退休字段；服务端清理旧实体与修订、学习作业及事件 / 检查点、学习元数据、导入快照中的旧字段。阻止工作区同步重新生成旧题库。保留账号、资料、原文和问答。隔离数据验证通过，本机服务重启后也确认保护数据摘要不变、旧实体与作业为空。 | 通过 |
| F11 配额异常丢草稿 | 存储异常不再产生未捕获错误；显示保存失败和 Toast。实测同时阻断保存接口与 LocalStorage，输入新笔记，保持异常刷新，草稿恢复；继续输入并关闭标签页，重新打开仍能从 IndexedDB 恢复；解除断连后数据库确实保存新文本。 | 通过 |

官方来源：<https://leetcode.cn/studyplan/top-100-liked/>。独立题单：`backend/xueya/data/hot100_official.json`。固定题库仍为 250 道：100 算法 + 100 基础 + 50 面试。
