## 已修复问题

1. 主聊天仍调用旧 Agent，C 的通用问答和问候路由没有进入主服务。
2. A 上传路径仍调用平台旧 `parse-document`；B 的结构解析/安全替换没有成为默认上传路径。
3. D 的概念/复习/计划查询读取旧实体，C 的同库学习产物没有完整映射。
4. C 预览生成中仍可点击确认；旧弹窗延迟到达的 close 事件还可能清掉新预览。现在处理期间禁用业务按钮，已重新打开的弹窗忽略旧 close；浏览器回归也等待真实可操作状态。
5. C 混合产物按 ID 取前 20 条，某类产物可能被其他内容挤出。改为先按当前页面的种类过滤，再分页；切换页面重新查询，不再只显示前 8 个学习包。
6. 旧知识点/出题接口把非法来源改成第一条原文。现在丢弃非法引用，全部无效时明确失败；跨课程与伪造正文不能替代同库原文。
7. 资料章节整理未保存到服务端、纠错仅有草稿、PPTX 上传入口缺失。现已保存章节，接通块级纠错与重新发布，开放服务端 PPTX 上传。Python 正文偏移按 Unicode 码点计算，前端纠错相应转换，避免 emoji 前后的未修改正文被截错。
8. OCR/向量索引只能调用接口，没有页面入口。资料页进阶区域现显示配置状态、资料选择与明确费用确认，后台进度和取消复用“本地数据”。`.env.example` 补齐可选配置。
9. C 课程总正文超过生成预算时，整个页面也无法加载。页面改用有界原文目录，可先选择少量资料；生成仍读取完整证据并严格执行预算。
10. 主聊天在没有浏览器迁移快照时未使用新上传的服务器资料；现在直接读取课程仓库，记录运行。模型返回前再次检查原文是否已删除/更新，不发布失效引用。
11. 通用问答补入上海时区的服务器日期和星期，保留“无课程引用”的边界；失败不会显示成在线成功。
12. Windows CLI 测试按 GBK 解码 UTF-8 子进程输出；已显式使用 UTF-8。初轮也出现过 SDK/HTTP 连接回收警告；不通过屏蔽警告处理，专项复核与后续全量结果见下文。
