# 普通聊天延迟排查与修复

日期：2026-10-23（Asia/Shanghai）。主程序仍为 `backend/xueya/server.py`。

## 后续纠正：普通聊天仍会因模型输出正文而失败

用户随后在原有 32 条消息的会话里询问“雷军是谁”，仍遇到回答格式错误。此前仅用短上下文的成功样例验收不足，不能据此宣布普通聊天已整体修好。

按页面可见的最近八条消息构造诊断请求后，抓到模型实际返回的是一段正常的中文人物介绍，耗时 1.859 秒，无传输错误，即使请求带有 JSON 格式参数也未返回 JSON。旧实现把该正文作为 JSON 解析失败，最终丢弃了正确返回的文字。原始诊断保留在本机 `.xueya-data/general-multiturn-diagnostic.json`，本次诊断费用保守预留 0.006562 元，此前累计上界 0.039373 元，两者合计 0.045935 元。

最终方案是主服务通用聊天接收自然语言正文，不要求模型生成接口 JSON；由宿主对每段正文执行 JSON 字符串转义，保持原有前端可读取的 `content` 与 `done.answer` 契约。普通正文、Markdown、用户所需的代码/JSON 示例均作为正文处理；空回答、输出截断和连接失败仍拒绝发布为完整回答。课程引用、结构化学习任务和旧兼容默认路径继续使用严格校验。新增带旧错误回复的八条历史、新会话、HTTP/SSE、分段引号/换行/代码等回归。

最终完整后端检查 372 项通过（仍有两条 Windows 资源回收警告），前端回归 41 项通过。重启后直接在用户原来的会话中发送一次“雷军是谁”，页面从 32 条增至 34 条消息，已实际显示完整人物介绍；模型调用账本耗时 1.116 秒，正常结束。未创建新会话来规避历史上下文。截图位于本机 `.xueya-data/chat-verified.jpg`，验证记录为 `.xueya-data/chat-live-verification.json`。

此次页面验证的上游未报告 token 用量，因此按宿主允许的最大八条历史、每条 5000 字符、4000 字符问题与 4096 输出 token 保守预留 0.20 元，而不将未知用量计为免费。与诊断及此前测试累计上界 0.245935 元，仍在用户授权的 1 元之内；未自动重试。

## 确认的耗时

页面发送的上下文包含课程资料，即使当前问题与资料无关，原工作流也会启动一个新的 Python stdio MCP 服务，随后检索失败再转通用问答。五次无外部 API 的对照中，模型调用前平均耗时 1855.58 ms，范围 1758.68–1951.25 ms。使用相同工具、相同检索和参数校验的同进程 MCP 会话后，平均 7.34 ms，范围 6.62–8.37 ms。

主模型传输原先每次新建 HTTP 客户端。真实网络跟踪中，新的 TLS 握手约 0.60–0.68 秒，另有一次握手约 5 秒后失败。连接池随 FastAPI 生命周期建立和关闭；逐请求超时、API 并发许可、预算及模型账本继续复用原平台。

仅共享客户端还不足以复用连接：SSE 收到 `[DONE]` 即退出时，HTTP 正文收尾尚未读完，连接会被丢弃。现在正常消费 HTTP 收尾，同时忽略 `[DONE]` 后的内容。真实本地 HTTP 测试确认连续请求使用同一 TCP 连接；取消时关闭响应并释放许可，后续请求仍可完成。独立 stdio MCP 入口继续保留。

## 真实 API 样例

同一问题、同一提示词和浏览器资料上下文，两侧均关闭深度思考；旧侧恢复每次启动 stdio 和每次新建客户端，新侧使用同进程工具及连接池。时间为进入工作流到最终 `done`，包含上游等待与生成，不是仅模型推理时间。

| 问题 | 旧侧 | 新侧 |
| --- | ---: | ---: |
| 今天星期几 | 9.04 秒 | 2.90 秒 |
| 1+1 等于几 | 7.04 秒 | 2.87 秒 |

这两组样例不是长期延迟保证，端到端差额也不能全部归因于代码优化。可重复验证的稳定收益是消除约 1.85 秒的本地工具启动；连接保活时还可省去新连接与握手。上游响应头等待仍有约 1.6–5.3 秒波动。

一个采用 512-token 测试上限的请求返回 `length`，另一个新样例在 TLS 握手阶段失败。各自批次立即停止，未自动重试。第二批采用正式输出上限并使用不同的独立问题。失败样例仍保留在记录中，没有计算为提速成功。

## 预算与复现

用户授权累计最多 1 元，包括此前四次深度思考对比。前后共 11 次外部调用，包含两次失败；按每次完整输出上限和保守输入预留，累计费用上界为 0.039373 元，实际账单可能更低。价格基于[官方 Flash 价格](https://mimo.mi.com/models/zh-CN/mimo-v2.6-flash)，缓存输入按未命中价格保守估算，未知用量不退还预留。

`scripts/profile_chat_latency.py` 必须显式传入预算、上一份报告和新的输出路径；默认拒绝覆盖报告，不自动重试。脚本仅发送合成问题与项目样例课程内容，记录事件名称、耗时和用量，不保存密钥、请求头或原始网络跟踪详情。原始计时报告保留在本机 `.xueya-data/`。

HTTP/SSE 路径和事件类型保持，宿主负责普通聊天正文的 JSON 转义；课程证据验证、只读工具白名单、课程隔离及取消语义保持。网络连接复用遵循 [HTTPX 客户端生命周期建议](https://www.python-httpx.org/async/)。
