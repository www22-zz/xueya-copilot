# B / C 合并到 main 的接入说明

日期：2026-10-17。基线：main 的 B 合并提交 `4c28634`；合入 C 提交 `015b3d5`。本次真实付费 API 调用次数：0。

## 现在如何启动和验证

```powershell
python -m pip install -r requirements.lock
python -m backend.xueya.server
python -m pytest -q
```

`python -m backend.server` 和 `npm start` 都启动同一个主服务。主环境保留 MCP 2.3.0，新增 fsrs 6.3.2 / pytest-asyncio 1.4.0；不按 C 旧 requirements 安装 MCP 1.x。requirements.txt 转引统一锁文件。测试同时收集 `tests/python` 与 `tests_python`，原有前端、浏览器检查保留。

## 代码的职责

- `backend/xueya/`：main 主服务、SQLite、作业、资源、模型调用账本、D 的 MCP 和 B 的结构化 RAG。B 已合并的代码和历史不被 C 的旧平台覆盖。
- `backend/agent/`：C 的回答证据验证、章节总结/学习包、测验与订正、知识结构、学习计划、FSRS 复习、推荐反馈、可恢复工作流、媒体领域接口。
- `backend/xueya/learning_integration.py`：主平台到 C 的实际适配。复用同一数据库、文件和模型请求资源；学习产物与 B 文档 artifact 使用不同 ID 命名空间，避免冲突。确认写入有事务、版本条件和操作回执，同一个操作重放返回原始结果。
- C 同时带来的 `backend/app.py`、`backend/platform/`、`backend/mcp/` 等保留为 C 独立交付的兼容工厂及测试依赖，**不是主服务的生产入口**。其 MCP API 已适配统一 2.3 SDK；新功能不要继续扩展第二套平台。
- `frontend/` 和 `shared/` 保留 main 的 A 页面；接纳 C 的通用问答显示和任务路由小改动。C 的学习功能已在各页进阶区域接线，原浏览器页面与记录保留。

## 主服务已接通的路径

默认开启平台时，主服务注册 B 的 `/api/platform/rag/*` 和 C 的 `/api/learning/*`；原有 HTTP/SSE、原件、工作区、MCP、备份和启动逻辑保持。

调用 C 接口需与主服务同源、本机 Host，并附上 `/api/platform/bootstrap` 返回的 `X-Xueya-Token`。课程由 URL `?courseId=...` 绑定，默认 `course-default`，请求体不能跨课程。选择资料使用 `selection: {documentIds, section, sourceIds}` 的可选字段，不接收客户端伪造的原文或题目内容。

C 的来源优先读取 B 当前有效的完整资料片段；旧版已入库资料使用服务端原文兼容。文档替换、修正或删除后，原快照失效，章节工作流不能拿旧快照继续写入；学习包和记忆卡新采纳也检查证据。模型与检索都仅调用外部 API；未配置模型时明确返回原文摘录。

已挂载的服务包括：资料回答、候选出题、测验预览/确认/作答/订正、错因订正、学习包/计划预览和采纳、笔记编辑、记忆卡/FSRS、复习队列、每日学习编排、推荐反馈，以及章节任务创建/查询/恢复/取消。详尽请求字段仍见 C-integration.md 的路由契约，Python 实现以代码为准。

章节任务进入现有持久化队列，run/检查点持久化；生成后停在确认阶段，确认后才保存。远端结果不明不会自动重放；服务重启后将中断中的 C run 转为需要检查的状态。草稿仅存在服务端，24 小时有效。模型请求复用 main 的并发与调用账本，取消章节工作流会取消其模型请求并释放资源。
